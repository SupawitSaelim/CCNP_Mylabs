🔹 สรุปทฤษฎี VRRPv3 🔹

1. ความหมาย

VRRP (Virtual Router Redundancy Protocol) คือโปรโตคอลที่ทำให้สามารถมี Default Gateway เสมือน (Virtual Router) ได้ เพื่อความต่อเนื่องของการเชื่อมต่อหาก Gateway จริงตัวใดตัวหนึ่งล่ม

ความสำคัญ: VRRPv3 เป็นเวอร์ชั่นที่พัฒนาต่อจาก VRRPv2 โดยเพิ่มการรองรับ IPv6 และปรับปรุงความเร็วในการ Failover ให้ดียิ่งขึ้น

2. จุดเด่น

  • Open standard (RFC 5798) ใช้ข้ามผู้ผลิตได้ ทำให้สามารถทำงานร่วมกันได้ระหว่างอุปกรณ์ต่างผู้ผลิต
  • รองรับ IPv4 และ IPv6 ทำให้ใช้งานได้ทั้งสองโปรโตคอลในเครือข่าย
  • Preemption เปิดใช้งานโดยอัตโนมัติ ช่วยให้ Router ที่มี Priority สูงกว่าจะกลับมาเป็น Master โดยอัตโนมัติเมื่อกลับมาออนไลน์
  • รองรับ Object Tracking ปรับลด Priority ตามสถานะของ Interface หรือสิ่งที่ Track ช่วยให้การ Failover มีความชาญฉลาดมากขึ้น

3. ค่าพื้นฐาน

  • Priority ค่าเริ่มต้น = 100 (สูงสุดคือ 254)
  • Router ที่มี Priority สูงสุดจะเป็น Master
  • หาก Priority เท่ากัน IP สูงสุดจะเป็นตัวเลือก
  • Advertisement Interval: 1 วินาที (สามารถปรับได้ตั้งแต่ 0.1 วินาที)

4. โครงสร้าง

VRRPv3 ใช้คำสั่ง address-family เพื่อแยก IPv4/IPv6

  • IPv4 ใช้ IP ปกติ
  • IPv6 ต้องกำหนด link-local address เอง (ไม่สร้างให้อัตโนมัติแบบ HSRP)

แผนภาพการทำงานของ VRRP

    +-----------------+                +-----------------+
    |    Router A     |                |    Router B     |
    |  (Master VRRP)  |                | (Backup VRRP)   |
    |   Priority 200  |                |   Priority 100  |
    +--------+--------+                +--------+--------+
             |                                  |
             |                                  |
             +----------------------------------+
                             |
                    Virtual IP: 10.0.0.1
                    Virtual MAC: 00-00-5E-00-01-XX
                             |
                             |
                      +------+------+
                      |  End Device  |
                      |  Default GW: |
                      |   10.0.0.1   |
                      +-------------+

💡 VRRP ทำงานอย่างไร

  1. Router ทุกตัวในกลุ่ม VRRP จะถูกกำหนด Group ID และ Virtual IP เดียวกัน
  2. Router ที่มี Priority สูงสุดจะเป็น Master และตอบสนองต่อ ARP Request สำหรับ Virtual IP
  3. Master จะส่ง VRRP Advertisement เป็นระยะๆ เพื่อแจ้งสถานะ
  4. หาก Backup Router ไม่ได้รับ Advertisement เป็นเวลา 3 ครั้งติดต่อกัน จะเริ่มกระบวนการเลือก Master ใหม่
  5. สำหรับ VRRPv3 สามารถตั้งค่า Advertisement Timer ได้ละเอียดถึง 0.1 วินาที

5. จุดเด่นของ VRRPv3 เมื่อเทียบกับ VRRPv2

  • รองรับ IPv6: เพิ่มความสามารถในการใช้งานใน IPv6 network
  • Advertisement เร็วขึ้น: สามารถตั้ง timer ได้ละเอียดถึง 0.1 วินาที ช่วยให้การ failover เร็วขึ้น
  • Format คำสั่งใหม่: ใช้ address-family แยกการตั้งค่า IPv4/IPv6 ชัดเจน
  • รองรับ VMAC (Virtual MAC): ช่วยลดจำนวน ARP update เมื่อเกิดการ failover

🔸 คำสั่งที่จำเป็นทั้งหมด

🔹 Global Configuration (เปิด VRRPv3):

fhrp version vrrp v3

🔹 สร้าง VRRP group (IPv4):

interface vlan XX
vrrp <group-id> address-family ipv4
address <virtual-ip>
priority <value> # (ไม่ใส่ก็จะใช้ค่า default 100)

🔹 สร้าง VRRP group (IPv6):

interface vlan XX
vrrp <group-id> address-family ipv6
address <link-local-address> primary
priority <value>

🔹 แสดงสถานะ VRRP:

show vrrp
show vrrp brief

🔹 สร้าง Object Tracking:

track <id> interface <interface-name> line-protocol

🔹 ผูกการ Track กับ VRRP:

interface vlan XX
vrrp <group-id> address-family <ipv4|ipv6>
track <id> decrement <value>

🔹 ตั้งค่า Advertisement Interval:

interface vlan XX
vrrp <group-id> address-family <ipv4|ipv6>
timers advertise <centiseconds>

🔹 ปิดการใช้งาน Preemption:

interface vlan XX
vrrp <group-id> address-family <ipv4|ipv6>
no preempt

🔹 ตั้งค่า Preemption Delay:

interface vlan XX
vrrp <group-id> address-family <ipv4|ipv6>
preempt delay minimum <seconds>

⚠️ ข้อควรระวังสำหรับ IPv6

เมื่อตั้งค่า VRRP สำหรับ IPv6 ต้องระบุ link-local address เป็น primary ก่อนเสมอ และต้องกำหนด link-local address เอง ไม่เหมือน HSRP ที่สร้างให้อัตโนมัติ

การใช้งานขั้นสูง

1. การใช้ Object Tracking ที่ซับซ้อน

นอกจากการ track interface แล้ว ยังสามารถติดตามสถานะอื่นๆ ได้:

! ติดตาม IP SLA
ip sla 1
icmp-echo 8.8.8.8
frequency 5
ip sla schedule 1 start-time now life forever

! สร้าง Track object
track 10 ip sla 1 reachability

! ผูกกับ VRRP
interface vlan 10
vrrp 1 address-family ipv4
track 10 decrement 30

2. การตั้งค่า Multiple Virtual IP

VRRPv3 สามารถมีได้หลาย Virtual IP ในกลุ่มเดียวกัน:

interface vlan 20
vrrp 1 address-family ipv4
address 192.168.1.1 primary
address 192.168.1.2 secondary
address 192.168.1.3 secondary

3. การใช้ BFD (Bidirectional Forwarding Detection) กับ VRRP

เพิ่มความเร็วในการตรวจจับความล้มเหลว:

! เปิดใช้งาน BFD
interface vlan 30
bfd interval 200 min_rx 200 multiplier 3

! ผูกกับ VRRP
vrrp 1 address-family ipv4
bfd

💡 ทริคการตั้งค่า VRRP อย่างมีประสิทธิภาพ

  1. ใช้ค่า Priority ที่มีช่วงห่างกันมากพอ: เช่น 200 และ 100 แทนที่จะเป็น 101 และ 100 เพื่อให้มีช่องว่างสำหรับการลดค่าจาก tracking
  2. ตั้งค่า Preemption Delay: เพื่อป้องกันการ flapping เมื่อ interface มีปัญหาไม่เสถียร
  3. ใช้ Object Tracking หลายตัว: track ทั้ง interface และการเชื่อมต่อ upstream เพื่อให้การ failover ชาญฉลาดมากขึ้น
  4. ตั้งค่า Advertisement Timer ให้เหมาะสม: ค่าต่ำทำให้ failover เร็วขึ้น แต่อาจเพิ่มภาระให้กับ CPU

4. การตั้งค่า VRRP สำหรับ IPv6

interface vlan 40
ipv6 address 2001:db8:1:1::10/64
ipv6 address fe80::10 link-local
vrrp 2 address-family ipv6
address fe80::1 primary
address 2001:db8:1:1::1/64
priority 200

5. การใช้ VRRP กับ VLAN Interface หลาย Interface (Load Sharing)

การกระจายโหลดโดยให้ Router แต่ละตัวเป็น Master สำหรับ VLAN ต่างกัน:

Router A

interface vlan 10
vrrp 1 address-family ipv4
address 192.168.10.1
priority 200

interface vlan 20
vrrp 2 address-family ipv4
address 192.168.20.1
priority 100

Router B

interface vlan 10
vrrp 1 address-family ipv4
address 192.168.10.1
priority 100

interface vlan 20
vrrp 2 address-family ipv4
address 192.168.20.1
priority 200

จุดเด่นของ VRRPv3

  • ความเข้ากันได้: ทำงานข้ามผู้ผลิตได้ ไม่จำกัดเฉพาะอุปกรณ์ Cisco
  • ความเร็ว: Advertisement timer ละเอียดถึง 0.1 วินาที ช่วยให้ failover เร็วขึ้น
  • IPv6 Native: ออกแบบมาให้รองรับ IPv6 อย่างเต็มรูปแบบ

ข้อจำกัดของ VRRPv3

  • ไม่มี Load Balancing: ไม่มีกลไก load balancing แบบอัตโนมัติเหมือน GLBP ต้องทำ manual config
  • ไม่มี Authentication: VRRPv3 ตัด MD5 authentication ออกไปเพื่อความเรียบง่าย
  • ทรัพยากร: การตั้งค่า advertisement interval ต่ำมากอาจเพิ่มภาระให้ CPU
