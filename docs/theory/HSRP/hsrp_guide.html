ส่วนที่ 1: ทฤษฎีเกี่ยวกับ HSRP

HSRP คืออะไร?

Hot Standby Router Protocol (HSRP) เป็นโปรโตคอลที่พัฒนาโดย Cisco เพื่อให้ความสามารถในการทำ First Hop Redundancy Protocol (FHRP) ซึ่งช่วยเพิ่มความพร้อมใช้งาน (High Availability) ของเกตเวย์เริ่มต้นในเครือข่าย

HSRP ช่วยให้อุปกรณ์เครือข่ายสามารถทำงานร่วมกันเพื่อนำเสนอเกตเวย์เสมือน (Virtual Gateway) ที่ทำงานเป็นเกตเวย์เริ่มต้นสำหรับอุปกรณ์ปลายทางในเครือข่าย

เวอร์ชันของ HSRP

  • HSRPv1 - เวอร์ชันดั้งเดิม สนับสนุนเฉพาะ IPv4
  • HSRPv2 - เวอร์ชันที่ปรับปรุงแล้ว สนับสนุนทั้ง IPv4 และ IPv6, มีความสามารถเพิ่มเติมและประสิทธิภาพที่ดีกว่า

หมายเหตุ: ในการกำหนดค่า HSRPv2 จำเป็นต้องใช้คำสั่ง standby version 2 ก่อนการกำหนดค่าอื่นๆ

พารามิเตอร์สำคัญของ HSRP

พารามิเตอร์ คำอธิบาย ค่าเริ่มต้น
Group Number หมายเลขกลุ่ม HSRP (1-4095 สำหรับ HSRPv2) -
Priority ค่าความสำคัญที่ใช้เพื่อกำหนดว่าอุปกรณ์ใดควรเป็น Active Router 100
Hello Time ระยะเวลาระหว่างการส่งข้อความ Hello 3 วินาที (HSRPv1), 1 วินาที (HSRPv2)
Hold Time ระยะเวลาที่อุปกรณ์จะรอก่อนที่จะถือว่า Active Router ล้มเหลว 10 วินาที (HSRPv1), 3 วินาที (HSRPv2)
Preemption อนุญาตให้อุปกรณ์ที่มีค่าความสำคัญสูงกว่าสามารถแทนที่อุปกรณ์ที่มีค่าความสำคัญต่ำกว่าเป็น Active Router ปิดใช้งาน

พอร์ตการสื่อสารของ HSRP

HSRP ใช้พอร์ต UDP หมายเลข 1985 สำหรับการสื่อสารระหว่างอุปกรณ์ในกลุ่ม HSRP เดียวกัน มีการส่งแพ็กเกจไปยังที่อยู่มัลติแคสต์:

  • HSRPv1: 224.0.0.2 (IPv4)
  • HSRPv2: 224.0.0.102 (IPv4) หรือ FF02::66 (IPv6)

สถานะของ HSRP

  • Initial - สถานะเริ่มต้นเมื่อ HSRP เพิ่งเริ่มต้น
  • Listen - อุปกรณ์รับข้อความ Hello แต่ยังไม่เข้าร่วมในการเลือกตั้ง
  • Speak - อุปกรณ์ส่งข้อความ Hello และเข้าร่วมในการเลือกตั้ง
  • Standby - อุปกรณ์เป็นตัวเลือกถัดไปที่จะเป็น Active Router
  • Active - อุปกรณ์ทำหน้าที่ส่งต่อแพ็กเกจและตอบสนองต่อ ARP

การเปลี่ยนสถานะใน HSRP เกิดขึ้นตามเงื่อนไขต่างๆ:

  • เมื่อมีการเริ่มต้น interface อุปกรณ์จะเข้าสู่สถานะ Listen
  • หลังจากนั้นจะเข้าสู่สถานะ Speak เพื่อเข้าร่วมการเลือกตั้ง
  • อุปกรณ์ที่มี priority สูงสุดจะเข้าสู่สถานะ Active
  • อุปกรณ์ที่มี priority สูงรองลงมาจะเข้าสู่สถานะ Standby
  • อุปกรณ์อื่นๆ จะคงอยู่ในสถานะ Listen
🔹 ส่วนที่ 2: การกำหนดค่าและสังเกตการณ์ HSRP สำหรับ IPv4 และ IPv6

Switch D1 Configuration:

interface vlan 11
standby version 2
standby 11 ip 10.11.0.254
standby 11 priority 150
standby 11 preempt
standby 116 ipv6 autoconfig
standby 116 priority 150
standby 116 preempt

interface vlan 21
standby version 2
standby 21 ip 10.21.0.254
standby 21 preempt
standby 216 ipv6 autoconfig
standby 216 preempt

Switch D2 Configuration:

interface vlan 11
standby version 2
standby 11 ip 10.11.0.254
standby 11 preempt
standby 116 ipv6 autoconfig
standby 116 preempt

interface vlan 21
standby version 2
standby 21 ip 10.21.0.254
standby 21 priority 150
standby 21 preempt
standby 216 ipv6 autoconfig
standby 216 priority 150
standby 216 preempt

คำอธิบาย: ในการกำหนดค่าข้างต้น, D1 มีค่า priority สูงกว่า (150) สำหรับ VLAN 11 และ D2 มีค่า priority สูงกว่า (150) สำหรับ VLAN 21 ซึ่งหมายความว่า D1 จะเป็น Active Router สำหรับ VLAN 11 และ D2 จะเป็น Active Router สำหรับ VLAN 21

ตรวจสอบ HSRP:

show standby brief

คำสั่งเพิ่มเติมสำหรับการตรวจสอบ HSRP:

show standby
show standby vlan 11
show standby vlan 21
show standby all
🔹 ส่วนที่ 2.5: การปรับแต่ง HSRPv2 Timers

การปรับแต่ง Timers ช่วยลดเวลาในการตรวจจับความล้มเหลวและการกู้คืน ทำให้การเปลี่ยนแปลงระหว่าง Active Router และ Standby Router เร็วขึ้น

ข้อควรระวัง: ก่อนทำการปรับแต่ง Timers ให้ทำการ shutdown VLAN interface ก่อนและเปิด no shutdown หลังจากการตั้งค่าเสร็จสิ้น เพื่อป้องกันความผิดพลาดที่อาจเกิดขึ้นระหว่างการเปลี่ยนแปลง

ลดเวลาตรวจจับล้มเหลว:

interface vlan 11
standby 11 timers msec 250 msec 750

interface vlan 21
standby 21 timers msec 250 msec 750

คำอธิบาย: คำสั่งข้างต้นกำหนดให้ Hello Time เป็น 250 มิลลิวินาที (0.25 วินาที) และ Hold Time เป็น 750 มิลลิวินาที (0.75 วินาที) ซึ่งทำให้การตรวจจับความล้มเหลวของ Active Router เร็วขึ้นมาก

🔹 ส่วนที่ 3: การกำหนดค่า HSRP Authentication

การรับรองความถูกต้อง (Authentication) เป็นสิ่งสำคัญเพื่อป้องกันการโจมตีแบบปลอมแปลง HSRP หรือการแทรกแซงการทำงานของ HSRP ในเครือข่าย

Switch D1 Authentication:

interface vlan 11
standby 11 authentication md5 key-string Super53cret

interface vlan 21
standby 21 authentication md5 key-string Super53cret

หมายเหตุสำคัญ: ต้องทำการกำหนดค่าเดียวกันบน D2 เพื่อให้ HSRP สามารถทำงานได้ทั้งคู่ หากค่าต่างกันจะเกิด mismatch และ HSRP จะล้มเหลว

วิธีการรับรองความถูกต้องใน HSRP:

  • Plain Text Authentication - ใช้รหัสผ่านแบบข้อความธรรมดา (ไม่แนะนำสำหรับการใช้งานจริง)
  • MD5 Authentication - ใช้การเข้ารหัสแบบ MD5 ซึ่งปลอดภัยกว่า
🔹 ส่วนที่ 4: การกำหนดค่าและสังเกตการณ์ HSRP Object Tracking

Object Tracking ช่วยให้ HSRP สามารถปรับตัวตามสถานะของอินเทอร์เฟสหรือทรัพยากรอื่นๆ ในเครือข่าย ช่วยเพิ่มความยืดหยุ่นและความน่าเชื่อถือในการทำงาน

Step 1: สร้าง Tracked Object

track 1 interface g0/1 line-protocol

Step 2: นำ Object Tracking มาใช้กับ HSRP

ตัวอย่างให้ลด priority ลง 50 เมื่อ track interface ล้มเหลว:

interface vlan 11
standby 11 track 1 decrement 50

interface vlan 21
standby 21 track 1 decrement 50

คำอธิบาย: เมื่อลิงก์ที่ track อยู่นั้นล้มเหลว (เช่น G0/1 down) router จะลด priority และถ้าต่ำกว่าอีกฝั่งที่มี preemption ก็จะยอมสละสถานะ active ทำให้เกิดการ failover ไปยัง Standby Router โดยอัตโนมัติ

ประเภทของ Object Tracking:

  • Interface Line Protocol - ติดตามสถานะของอินเทอร์เฟส (up/down)
  • IP Route Reachability - ติดตามความสามารถในการเข้าถึงเส้นทาง IP
  • IP SLA Operations - ติดตามผลลัพธ์ของการดำเนินการ IP SLA

เคล็ดลับ: ใช้ Object Tracking ร่วมกับ preemption เพื่อให้เกิดการ failover อัตโนมัติเมื่อลิงก์กลับมาทำงานปกติ
