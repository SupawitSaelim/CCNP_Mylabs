Loop Guard ในระบบ Spanning Tree Protocol

การป้องกัน Loop ในกรณีที่พอร์ตไม่ได้รับ BPDU (Bridge Protocol Data Unit)

Loop Guard คืออะไร?

Loop Guard เป็นฟีเจอร์ของ Spanning Tree Protocol (STP) ที่ใช้ป้องกันการเกิด Loop ในกรณีที่พอร์ต Root Port หรือ Blocked Port หยุดรับ BPDU

  • ถ้า Root Port หรือ Blocked Port ไม่ได้รับ BPDU → พอร์ตจะเข้าสู่ Loop Inconsistent State และหยุดส่งทราฟฟิก
  • เมื่อ BPDU กลับมา → พอร์ตจะกลับมาทำงานอัตโนมัติ

Loop Guard ใช้กับพอร์ตไหน?

ใช้กับ Root Port และ Blocked Port เท่านั้น

  • Root Port → ป้องกันไม่ให้กลายเป็น Designated Port ถ้าหยุดรับ BPDU
  • Blocked Port (Alternate/Backup Port) → ป้องกันไม่ให้กลายเป็น Forwarding Port ถ้าหยุดรับ BPDU
คำเตือน: Loop Guard ไม่ควรเปิดใช้งานบนพอร์ตที่เป็น Designated Port เนื่องจากอาจส่งผลกระทบต่อการทำงานของ STP และอาจทำให้เครือข่ายทำงานผิดพลาด

วิธีตั้งค่า Loop Guard

1 เปิด Loop Guard บนพอร์ตที่ต้องการ
Switch(config)# interface <interface> Switch(config-if)# spanning-tree guard loop

หรือกำหนดหลายพอร์ตพร้อมกัน

Switch(config)# interface range <interface1>, <interface2>, ... Switch(config-if-range)# spanning-tree guard loop
2 เปิด Loop Guard แบบ Global
Switch(config)# spanning-tree loopguard default

(จะเปิดใช้งาน Loop Guard ทุกพอร์ตที่เป็น Root Port หรือ Blocked Port)

การทดสอบ Loop Guard

1 ตรวจสอบว่ามี Loop Guard อยู่บนพอร์ตหรือไม่
Switch# show running-config | include spanning-tree guard loop
2 ปิดการส่ง BPDU บนพอร์ตฝั่งตรงข้าม เพื่อจำลองการหยุดรับ BPDU
OtherSwitch(config)# interface <interface> OtherSwitch(config-if)# spanning-tree bpdufilter enable
3 ตรวจสอบว่าพอร์ตเข้าสู่ Loop Inconsistent State หรือไม่
Switch# show spanning-tree inconsistentports

ถ้าพอร์ตถูกบล็อค จะขึ้น Loop Inconsistent

4 ตรวจสอบสถานะพอร์ตที่ถูกบล็อค
Switch# show spanning-tree interface <interface>

พอร์ตที่ถูกบล็อคจะอยู่ในสถานะ BKN (Broken) และขึ้น LOOP_Inc (Loop Inconsistent)

วิธีแก้ไขพอร์ตที่ถูกบล็อคจาก Loop Guard

1 ลบ Loop Guard ออกจากพอร์ต (ถ้าจำเป็นต้องเปลี่ยนการตั้งค่า)
Switch(config)# interface <interface> Switch(config-if)# no spanning-tree guard loop
2 ตรวจสอบว่า BPDU กลับมาหรือยัง
3 รอให้พอร์ตกลับมาทำงานอัตโนมัติ หรือใช้คำสั่ง shutdown และ no shutdown รีเซ็ตพอร์ต
Switch(config)# interface <interface> Switch(config-if)# shutdown Switch(config-if)# no shutdown

ความแตกต่างระหว่าง Loop Guard และ UDLD

Loop Guard และ UDLD (UniDirectional Link Detection) เป็นฟีเจอร์ที่ช่วยป้องกัน Loop ในเครือข่าย แต่มีความแตกต่างกันดังนี้

คุณสมบัติ Loop Guard UDLD
การทำงาน ตรวจจับเมื่อไม่ได้รับ BPDU ตรวจจับการเชื่อมต่อแบบทางเดียว (Unidirectional)
โปรโตคอล ทำงานบน STP ทำงานเป็นโปรโตคอลแยกต่างหาก
การตรวจจับ ตรวจจับเมื่อไม่มี BPDU เข้ามาที่พอร์ต ตรวจจับว่าสัญญาณส่งไปแต่ไม่ได้รับกลับมา
เลเยอร์ที่ทำงาน เลเยอร์ 2 เลเยอร์ 2
การฟื้นฟู อัตโนมัติเมื่อได้รับ BPDU ต้องรีเซ็ตด้วยคำสั่ง (err-disable recovery)

ข้อดีของ Loop Guard

  • ป้องกัน Loop ที่อาจเกิดขึ้นจากการไม่ได้รับ BPDU
  • ช่วยรักษาเสถียรภาพของเครือข่ายเมื่อเกิดปัญหา
  • ทำงานอัตโนมัติและฟื้นฟูอัตโนมัติเมื่อปัญหาหมดไป
  • สามารถใช้งานร่วมกับ Root Guard และ UDLD เพื่อเพิ่มความปลอดภัยให้กับเครือข่าย

ข้อจำกัดของ Loop Guard

  • ใช้ได้เฉพาะกับ Root Port และ Blocked Port เท่านั้น
  • ไม่สามารถป้องกัน Loop ที่เกิดจากการที่พอร์ตไม่ได้รับการกำหนดค่า STP
  • จำเป็นต้องกำหนดค่าที่เหมาะสมเพื่อให้ทำงานได้อย่างมีประสิทธิภาพ

การใช้งาน Loop Guard ร่วมกับ Root Guard

Loop Guard และ Root Guard สามารถใช้งานร่วมกันเพื่อเพิ่มความปลอดภัยให้กับเครือข่าย โดยมีแนวทางดังนี้

  • Root Guard → ใช้กับ Designated Port เพื่อป้องกันการเปลี่ยนเป็น Root Port
  • Loop Guard → ใช้กับ Root Port และ Blocked Port เพื่อป้องกันการเกิด Loop
ข้อควรระวัง: ไม่ควรเปิดใช้งานทั้ง Root Guard และ Loop Guard บนพอร์ตเดียวกัน เนื่องจากอาจทำให้เกิดความขัดแย้งในการทำงานของ STP
