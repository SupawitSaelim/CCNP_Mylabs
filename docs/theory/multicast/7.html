PIM Dense Mode (PIM-DM)

แนวคิด Multicast Multicast บน Local LAN Multicast IP to MAC mapping IGMP IGMP Snooping PIM Dense Mode Summary Commands

PIM (Protocol Independent Multicast) เป็นโปรโตคอลที่ใช้ในการจัดการการส่งข้อมูลแบบ Multicast โดยมีโหมดการทำงานหลัก 2 โหมด คือ PIM Dense Mode (PIM-DM) และ PIM Sparse Mode (PIM-SM) บทความนี้จะอธิบายโหมดแรกคือ PIM Dense Mode

รูปที่ 1: PIM-DM Initial Topology - โทโพโลจีเริ่มต้นสำหรับการอธิบาย PIM-DM

PIM Dense Mode คืออะไร?

PIM Dense Mode เป็นวิธีการส่งข้อมูล Multicast แบบ "Push Model" โดยมีแนวคิดพื้นฐานคือ "ส่งข้อมูลไปยังทุกเราเตอร์ในเครือข่าย" ก่อน แล้วค่อยตัดเส้นทางที่ไม่ต้องการทิ้งในภายหลัง PIM-DM จะมีประสิทธิภาพสูงในกรณีที่มีผู้รับ (receivers) จำนวนมากกระจายอยู่ทั่วเครือข่าย แต่ในกรณีที่มีผู้รับน้อย โหมดนี้จะไม่มีประสิทธิภาพ

รูปที่ 2: PIM-DM Initial Flooding - การส่งข้อมูลเริ่มต้นไปยังทุกเราเตอร์ในเครือข่าย

PIM-DM เหมาะกับเครือข่ายขนาดเล็ก เช่น LAN/Campus ที่มีผู้รับจำนวนมากกระจายตัวอยู่ในเราเตอร์จำนวนไม่มาก

กลไกการทำงานของ PIM-DM

PIM Dense Mode ใช้โมเดลการส่งข้อมูลแบบ "flood-and-prune" ซึ่งประกอบด้วย 3 ขั้นตอนหลัก:

ขั้นตอนที่ 1: การส่งข้อมูลเริ่มต้น (Initial Flooding)

เราเตอร์ทุกตัวจะส่งข้อมูล multicast ไปยังทุกอินเตอร์เฟซที่เปิดใช้งาน PIM ยกเว้นอินเตอร์เฟซที่รับข้อมูลเข้ามา การส่งข้อมูลเริ่มจากเราเตอร์ต้นทาง (First-Hop Router หรือ FHR) และกระจายไปทั่วทั้งเครือข่าย ทำให้เราเตอร์ทุกตัวได้รับข้อมูล multicast

รูปที่ 3: ขั้นตอนการส่งข้อมูลเริ่มต้นจากแหล่งที่มาไปยังทุกเราเตอร์

กลไกป้องกันลูป Reverse Path Forwarding (RPF)

RPF เป็นกลไกป้องกันลูปของ PIM โดยเราเตอร์แต่ละตัวจะตรวจสอบว่าข้อมูล multicast ที่ได้รับมานั้นมาจากอินเตอร์เฟซที่ดีที่สุดในการเข้าถึงแหล่งที่มาของข้อมูล (source) ตามตารางเส้นทาง unicast หรือไม่

  • ถ้าเราเตอร์ได้รับข้อมูล multicast บนอินเตอร์เฟซ RPF (อินเตอร์เฟซที่ดีที่สุดในการเข้าถึงแหล่งที่มา) เราเตอร์จะยอมรับและส่งต่อข้อมูล
  • ถ้าเราเตอร์ได้รับข้อมูล multicast บนอินเตอร์เฟซอื่น เราเตอร์จะละทิ้งข้อมูลนั้น
รูปที่ 4: อินเตอร์เฟซ RPF (Reverse Path Forwarding) ที่ใช้ในการป้องกันลูป
รูปที่ 5: การทำงานของ RPF ในระดับ Data Plane

กลไก PIM Assert

เมื่อมีเราเตอร์หลายตัวต้องการส่งข้อมูล multicast บนเซกเมนต์เดียวกัน จะเกิดการซ้ำซ้อนของข้อมูล กลไก PIM Assert จะเลือกเราเตอร์เพียงตัวเดียวให้เป็นผู้ส่งข้อมูล (Assert Winner) เพื่อแก้ปัญหานี้

รูปที่ 6: กลไก PIM Assert ที่ใช้เลือกเราเตอร์เพียงตัวเดียวให้เป็นผู้ส่งข้อมูลบนเซกเมนต์ร่วม
ขั้นตอนที่ 2: การตัดแต่ง (Pruning)

หลังจากการส่งข้อมูลเริ่มต้นเสร็จสิ้น เราเตอร์จะเริ่มตัดแต่งการส่งข้อมูล multicast ที่ไม่จำเป็น:

  • ถ้าเราเตอร์ไม่มีผู้รับที่สนใจกลุ่ม multicast นั้น (ทั้งที่เชื่อมต่อโดยตรงหรือผ่านเราเตอร์ downstream) เราเตอร์จะส่งข้อความ PIM Prune ไปยังเราเตอร์ต้นทาง
  • ถ้าเราเตอร์ได้รับข้อมูล multicast บนอินเตอร์เฟซที่ไม่ใช่ RPF เราเตอร์จะส่งข้อความ PIM Prune กลับไปยังเราเตอร์ต้นทาง
รูปที่ 7: กระบวนการ Pruning ใน PIM-DM

การเผยแพร่ข้อความ Prune ไปยังต้นทาง

เมื่อเราเตอร์ได้รับข้อความ PIM Prune เราเตอร์จะหยุดการส่งข้อมูล multicast ไปยังอินเตอร์เฟซที่ส่งข้อความ Prune มา ถ้าเราเตอร์ต้นทางไม่มีผู้รับที่สนใจบนอินเตอร์เฟซอื่น ๆ มันจะส่งข้อความ Prune ต่อไปยังต้นทางถัดไป

การ Pruning บนเซกเมนต์ร่วม

บนเซกเมนต์ร่วมที่มีเราเตอร์หลายตัว กระบวนการ pruning จะซับซ้อนขึ้น เมื่อเราเตอร์ตัวหนึ่งส่งข้อความ PIM Prune เราเตอร์ตัวอื่นที่มีผู้รับสนใจจะต้องตอบกลับด้วยข้อความ PIM Join เพื่อรักษาการรับข้อมูล multicast ไว้

รูปที่ 8: การ Pruning บนเซกเมนต์ร่วม

การตั้งค่าเวลาหมดอายุของ Prune

เมื่อเราเตอร์ทำการ prune อินเตอร์เฟซ มันจะเริ่มจับเวลาหมดอายุของ prune สำหรับอินเตอร์เฟซนั้น (ค่าเริ่มต้นคือ 3 นาที) เมื่อเวลาหมดอายุ เราเตอร์จะเริ่มส่งข้อมูล multicast ไปยังอินเตอร์เฟซที่ถูก prune อีกครั้ง เว้นแต่จะได้รับข้อความ Prune ใหม่ก่อนหมดเวลา

การเชื่อมต่อใหม่ (Grafting)

ถ้าเราเตอร์ที่เคย prune ตัวเองออกจากกลุ่ม multicast ได้รับคำขอเข้าร่วมจากเราเตอร์ downstream หรือผู้รับที่เชื่อมต่อ มันจะส่งข้อความ PIM Graft ไปยังเราเตอร์ต้นทางเพื่อเชื่อมต่อกับ multicast distribution tree อีกครั้ง

ขั้นตอนที่ 3: การรีเฟรชสถานะ (State Refresh)

การดำเนินการ flood-and-prune เริ่มต้นส่งผลให้เกิด multicast distribution tree ที่มีรากจากแหล่งที่มา - เรียกว่า source path tree (SPT) อย่างไรก็ตาม การทำงานของ control plane ยังไม่เสร็จสิ้น PIM Dense Mode อาศัยการรีเฟรชสถานะเป็นระยะ สถานะ prune ไม่ถาวร มีตัวจับเวลาที่เกี่ยวข้อง เป็นระยะๆ เราเตอร์จะทำการส่งข้อมูล multicast อีกครั้งเพื่อให้แน่ใจว่าผู้รับใหม่ๆ จะได้รับข้อมูล ถ้ายังไม่มีผู้รับ กระบวนการ pruning จะเริ่มใหม่อีกครั้ง

รูปที่ 9: Source Path Tree (SPT) ที่เกิดขึ้นหลังจากกระบวนการ flood-and-prune

สรุป

PIM Dense Mode (PIM-DM) เป็นโหมดการทำงานของ PIM ที่ใช้วิธีการ "flood-and-prune" เพื่อส่งข้อมูล multicast จากแหล่งที่มาไปยังผู้รับที่สนใจ โดยเริ่มจากการส่งข้อมูลไปทั่วทั้งเครือข่าย แล้วตัดแต่งเส้นทางที่ไม่จำเป็นออกในภายหลัง เหมาะสำหรับเครือข่ายที่มีผู้รับจำนวนมากกระจายอยู่ทั่วทั้งเครือข่าย แต่อาจไม่มีประสิทธิภาพในเครือข่ายที่มีผู้รับน้อย
