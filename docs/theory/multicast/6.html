แนวคิดเกี่ยวกับ Multicast Routing

ในอดีต นักวิจัยเครือข่ายคิดว่าต้องมีโปรโตคอลการจัดเส้นทาง Multicast แยกต่างหากที่ทำงานคู่ขนานกับโปรโตคอลการจัดเส้นทาง Unicast เพื่อให้ IP Multicast ทำงานได้ โปรโตคอลเช่น MOSPF (Multicast Open Shortest Path First) และ DVMRP (Distance Vector Multicast Routing Protocol) ถูกนำมาใช้ในเวลานั้น

อย่างไรก็ตาม ต่อมาพบว่าโปรโตคอลการจัดเส้นทาง Unicast ได้ทำการคำนวณที่จำเป็นทั้งหมดไว้แล้ว และไม่จำเป็นต้องมีโปรโตคอล Multicast เต็มรูปแบบที่ทำการคำนวณเดียวกันซ้ำและสิ้นเปลืองทรัพยากรของเราเตอร์

Protocol Independent Multicast (PIM)

PIM ถูกพัฒนาขึ้นโดยใช้แนวคิดว่าโปรโตคอลการจัดเส้นทาง Multicast ไม่จำเป็นต้องคำนวณโทโพโลยีเต็มรูปแบบ แต่เพียงใช้ข้อมูลที่ได้จากการจัดเส้นทาง Unicast ที่มีอยู่แล้ว

"Protocol Independent" หมายความว่าไม่ขึ้นอยู่กับโปรโตคอลการจัดเส้นทาง Unicast เฉพาะใด สามารถใช้ข้อมูลที่ได้จากโปรโตคอลพื้นฐานใดๆ เช่น RIP, ISIS, EIGRP, OSPF, BGP ฯลฯ

PIM ทำงานโดยสร้างและรักษา Multicast Distribution Trees (MDT) โดยใช้ข้อมูลที่ได้จากโปรโตคอลการจัดเส้นทาง Unicast ตราบใดที่ตารางการจัดเส้นทาง Unicast มีความเสถียรและไม่มีลูป

Multicast Distribution Tree (MDT)

ในเครือข่าย คำว่า "tree" (ต้นไม้) ถูกใช้บ่อย โปรโตคอลหลายตัวใช้แนวคิดนี้เพื่ออธิบายกราฟของเส้นทางเครือข่ายจากจุดเริ่มต้นไปยังจุดสิ้นสุด

โดยทั่วไป เมื่อบางสิ่งถูกอธิบายว่าเป็น "ต้นไม้" มักหมายความว่ามีลักษณะสำคัญสี่ประการดังนี้:

  • ไม่มีลูป (Loop-free): ไม่มีวงจรหรือลูป
  • มีลำดับชั้น (Hierarchical): เติบโตจากรากผ่านกิ่งก้านและใบ
  • มีความแน่นอน (Deterministic): มีเพียงเส้นทางที่สั้นที่สุดหนึ่งเส้นจากจุด A ไปยัง B (ไม่มี ECMP)
  • มีทิศทาง (Directional): ขยายออกจากรากไปสู่ภายนอก

MDT เป็นโครงสร้างต้นไม้แนวคิดที่อธิบายเส้นทางที่ข้อมูล Multicast ไหลจากแหล่งกำเนิดไปยังผู้รับ

Shortest Path Tree (SPT)

SPT แสดงเส้นทางสั้นที่สุดจากแหล่งกำเนิดไปยังผู้รับ เป้าหมายของ PIM คือใช้ข้อมูลที่ได้จากโปรโตคอลการจัดเส้นทาง Unicast และสร้าง SPT เพื่อให้ Multicast จากแหล่งกำเนิดสามารถส่งไปยังผู้รับที่สนใจได้อย่างเหมาะสม

คำว่า Shortest Path Tree และ Source Path Tree ใช้แทนกันได้ในบริบทของ PIM ทั้งสองคำหมายถึงเส้นทางที่เหมาะสม แน่นอน ไม่มีลูป และสั้นที่สุดจากแหล่งกำเนิดไปยังผู้รับ

สังเกตว่าผู้รับแต่ละรายมี SPT ของตัวเอง และเส้นทาง Multicast อาจแตกต่างกันตามเส้นทางที่สั้นที่สุดจากแหล่งกำเนิดไปยังผู้รับแต่ละราย

การรู้จักแหล่งกำเนิด (S, G) และไม่รู้จักแหล่งกำเนิด (*, G)

การส่ง IP Multicast เป็นฟังก์ชันที่ไม่มีสถานะ (Stateless) แหล่งกำเนิดเพียงส่งแพ็กเก็ตไปยังที่อยู่กลุ่ม Multicast (เช่น 239.1.1.1) โดยไม่ต้องรู้จักหรือติดตามผู้รับแต่ละคน เครือข่ายรับผิดชอบในการส่งข้อมูล Multicast ไปยังผู้รับที่สนใจ (หากมี)

การรับ Multicast เป็นฟังก์ชันที่มีสถานะ (Stateful) ผู้รับต้องเข้าร่วมกลุ่ม Multicast ที่ต้องการรับอย่างชัดเจน

รู้จักแหล่งกำเนิด (S, G): ในบางกรณี ผู้รับรู้ที่อยู่ IP ของแหล่งกำเนิดสตรีม Multicast ที่ต้องการ ในกรณีนี้ เราเตอร์ Gateway ท้องถิ่นของผู้รับสามารถเริ่มสร้าง SPT ได้ทันทีเนื่องจากรู้ที่อยู่ IP ของแหล่งกำเนิด

ไม่รู้จักแหล่งกำเนิด (*, G): ในกรณีที่พบบ่อยที่สุด ผู้รับไม่รู้จักแหล่งกำเนิดที่ส่งข้อมูล Multicast ที่สนใจ เครือข่ายต้องติดตามว่ามีแหล่งกำเนิดที่ใช้งานอยู่หรือไม่ นี่คือเหตุผลที่เราต้องการ Rendezvous Point (RP)

Rendezvous Point (RP)

RP เป็นเราเตอร์ในเครือข่ายที่ทำหน้าที่เป็นจุดศูนย์กลางที่แหล่งกำเนิด Multicast และผู้รับลงทะเบียนในตอนแรก

เมื่อแหล่งกำเนิด Multicast เริ่มส่งข้อมูล Multicast มันจะส่งข้อมูลไปยัง RP โดยใช้ข้อความ PIM Register ดังนั้น RP จึงรู้จักแหล่งกำเนิดที่ใช้งานทั้งหมดในเครือข่าย

เมื่อผู้รับต้องการเข้าร่วมกลุ่ม Multicast เราเตอร์ Gateway ท้องถิ่นจะส่งข้อความ PIM Join ไปยัง RP ข้อความนี้ถามว่า RP มีแหล่งกำเนิดที่ใช้งานอยู่ที่ส่ง Multicast ไปยังกลุ่มนั้นหรือไม่

ต้องจำ:

  • เราเตอร์ Gateway ท้องถิ่นของแหล่งกำเนิดเรียกว่า First Hop Router (FHR)
  • เราเตอร์ Gateway ท้องถิ่นของผู้รับเรียกว่า Last Hop Router (LHR)

Rendezvous Point Tree (RPT)

RPT มักถูกเรียกว่า "Shared Tree" มีรากที่เราเตอร์ที่ทำหน้าที่พิเศษในโดเมน PIM เรียกว่า Rendezvous Point (RP) RP จัดการข้อมูลเกี่ยวกับแหล่งกำเนิด Multicast ในเครือข่าย

ในบริบทนี้ คำว่า Rendezvous Point Tree (RPT) อธิบายเส้นทางที่ไม่มีลูป แน่นอน และมีทิศทางจาก RP ไปยังผู้รับ

กระบวนการทำงานของ PIM

  1. เมื่อ FHR ได้รับสตรีม Multicast จากแหล่งกำเนิด มันจะลงทะเบียนแหล่งกำเนิดกับ Rendezvous Point (RP)
  2. เมื่อ LHR (เราเตอร์ Gateway ของผู้รับ) ได้รับ Multicast จาก RP มันเรียนรู้ที่อยู่ IP ของแหล่งกำเนิด จากนั้น LHR เริ่มสร้าง Shortest Path Tree (SPT) ไปยังแหล่งกำเนิด
  3. FHR ส่งข้อมูล Multicast โดยตรงไปยัง LHR และ Rendezvous Point ไม่ได้อยู่ในเส้นทางข้อมูลอีกต่อไป

สรุปสาระสำคัญ

  • PIM ใช้ข้อมูลที่ได้จากโปรโตคอลการจัดเส้นทาง Unicast และสามารถทำงานกับโปรโตคอลพื้นฐานใดๆ
  • PIM สร้าง Multicast Distribution Tree (MDT) สองประเภท: SPT และ RPT
  • การส่ง Multicast เป็นฟังก์ชันที่ไม่มีสถานะ (Stateless) ขณะที่การรับ Multicast เป็นฟังก์ชันที่มีสถานะ (Stateful)
  • Rendezvous Point (RP) ทำหน้าที่เป็นจุดศูนย์กลางที่รู้จักแหล่งกำเนิด Multicast ทั้งหมด
  • First Hop Router (FHR) คือเราเตอร์ Gateway ท้องถิ่นของแหล่งกำเนิด
  • Last Hop Router (LHR) คือเราเตอร์ Gateway ท้องถิ่นของผู้รับ
