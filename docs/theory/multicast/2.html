บทนำ

เอกสารนี้อธิบายถึงการทำงานของ Multicast บน Local LAN โดยเริ่มจากพื้นฐานกระบวนการ Encapsulation จนถึงความแตกต่างระหว่าง Unicast, Broadcast และ Multicast

กระบวนการ Encapsulation

Encapsulation คือกระบวนการเพิ่ม header รอบข้อมูลเมื่อข้อมูลเคลื่อนลงตามชั้นของโมเดล OSI โดยแต่ละชั้นจะทำหน้าที่เฉพาะและเพิ่ม header ของชั้นนั้นๆ ก่อนส่งต่อไปยังชั้นถัดไป เมื่อข้อมูลถูกส่งถึงปลายทาง จะเกิดกระบวนการ Decapsulation ในทิศทางตรงกันข้าม


รูปที่ 1: แสดงกระบวนการ Data Encapsulation

Encapsulation ใน Unicast

ในการสื่อสารแบบ Unicast เช่น เมื่อ PC1 เปิดเว็บเพจผ่าน HTTP:

  1. PC1 ตรวจสอบว่า IP ปลายทางอยู่ใน Subnet เดียวกันหรือไม่
  2. ถ้าไม่อยู่ใน Subnet เดียวกัน จะต้องส่งผ่าน Default Gateway
  3. ก่อนส่งข้อมูล PC1 ต้องรู้ MAC Address ของ Gateway โดยใช้ ARP Request
  4. Default Gateway ตอบกลับด้วย ARP Response แบบ Unicast
  5. หลังจากนั้น PC1 จึงมีข้อมูลเพียงพอในการ Encapsulate ข้อมูลและส่งไปยัง LAN
สิ่งสำคัญที่ต้องเข้าใจคือ ข้อมูลใน Layer 3 Header (SRC_IP และ DST_IP) ไม่เปลี่ยนแปลงตลอดทาง แต่ข้อมูลใน Layer 2 Header (SRC_MAC และ DST_MAC) จะเปลี่ยนแปลงทุกครั้งที่ข้ามไปยัง Layer 3 Hop ใหม่

ปัญหาของการใช้ Multicast บน LAN

เมื่อนำหลักการของ Unicast มาประยุกต์ใช้กับ Multicast บน LAN จะเกิดคำถามสำคัญ:

  • ควรใช้ MAC Address ใดเป็น Destination?
  • สวิตช์ LAN จะรู้ได้อย่างไรว่าควรส่งต่อ Frame ไปยัง Port ใดบ้าง?
  • สวิตช์ LAN จะแยกแยะ Multicast Stream ต่างๆ ได้อย่างไร?
  • อุปกรณ์ปลายทางจะประมวลผล Frame ที่ไม่ได้มี MAC Address ตรงกับของตนเองหรือไม่?

วิธีทำงานของ Multicast บน LAN

Multicast ทำงานแตกต่างจาก Unicast และ Broadcast ที่ระดับ Ethernet โดยมีความแตกต่างหลักคือการใช้ MAC Address ปลายทาง:

ประเภท Destination MAC Address
Unicast MAC Address ทางกายภาพของอินเตอร์เฟสปลายทาง (ค้นหาด้วย ARP)
Broadcast MAC Address สำหรับ Broadcast คือ 0xFFFF.FFFF.FFFF
Multicast สร้างจาก IP Address ของ Multicast ด้วยอัลกอริทึมเฉพาะ (ไม่ใช้ ARP)

Multicast MAC Address

IP Address ของ Multicast (224.0.0.0 ถึง 239.255.255.255) จะถูกแมปไปยัง Ethernet MAC Address ในช่วง 0100.5E00.0000 ถึง 0100:5E7F:FFFF ตามอัลกอริทึมที่กำหนดโดย IANA

Control-Plane ของ Multicast

สวิตช์ LAN ต้องรู้ว่าโฮสต์ใดสนใจ Multicast Group ใด และเชื่อมต่อกับพอร์ตใด โดยใช้โปรโตคอลดังนี้:

IGMP (Internet Group Management Protocol): โฮสต์ใช้ IGMP เพื่อแจ้งให้เราเตอร์ Multicast ในเครือข่ายท้องถิ่นทราบว่าต้องการรับ Traffic สำหรับกลุ่ม Multicast เฉพาะ

PIM (Protocol Independent Multicast): เราเตอร์ที่รองรับ Multicast ใช้ PIM เพื่อแลกเปลี่ยนข้อมูลกลุ่ม Multicast และสร้าง Multicast Distribution Tree

สวิตช์ LAN รับฟัง IGMP Membership Message จากโฮสต์และ PIM HELLO Message จากเราเตอร์ เพื่อสร้างตารางการส่งต่อ Multicast

Data-Plane ของ Multicast

จากการรับฟัง IGMP และ PIM Message สวิตช์จะสร้างตารางที่มีข้อมูลผู้รับที่เชื่อมต่อสำหรับแต่ละกลุ่ม Multicast และทำการสำเนา Frame ไปยังพอร์ตที่เกี่ยวข้องเท่านั้น
