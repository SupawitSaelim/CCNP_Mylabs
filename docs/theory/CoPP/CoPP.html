Control Plane Policing (CoPP)

คู่มือทฤษฎีและการกำหนดค่าสำหรับการปกป้อง Control Plane

ทฤษฎี: Control Plane Policing (CoPP)

CoPP เป็นฟีเจอร์สำหรับป้องกัน CPU ของ Control Plane บนเราเตอร์จากทราฟฟิกที่อาจทำให้ระบบไม่เสถียร เช่น ทราฟฟิกที่เกิดจาก การโจมตี DoS หรือปริมาณแพ็กเก็ตที่สูงผิดปกติ

CoPP ใช้ Modular QoS CLI (MQC) เพื่อควบคุมทราฟฟิกที่ส่งไปยัง Control Plane โดยสามารถกำหนดให้

  • อนุญาต (permit)
  • ปฏิเสธ (drop)
  • จำกัดอัตราการส่ง (rate-limit)

CoPP จะจัดการกับทราฟฟิกที่ต้องใช้ การประมวลผลโดย CPU ของเราเตอร์ เช่น

  • แพ็กเก็ตที่ถูกล็อกโดย ACL
  • แพ็กเก็ตที่มีตัวเลือกพิเศษใน IP header (TTL options)
  • ทราฟฟิกควบคุม เช่น Routing Protocols (OSPF, EIGRP, BGP)
  • ทราฟฟิกการจัดการ เช่น Telnet, SSH, SNMP, NTP, HTTP

Scenario: การกำหนดค่า CoPP บน R1

เป้าหมายของการกำหนดค่า CoPP ในแลบนี้คือ ใช้ MQC ในการป้องกัน CPU ของ Control Plane โดยทำตามขั้นตอนดังนี้

  1. กำหนด ACL เพื่อระบุทราฟฟิก
  2. สร้าง Class Map เพื่อจำแนกทราฟฟิก
  3. สร้าง Policy Map และกำหนดค่า policing
  4. นำ Policy Map ไปใช้กับ Control Plane
  5. ตรวจสอบผลลัพธ์ด้วย show commands
1
กำหนด ACL เพื่อระบุทราฟฟิก

เราจะใช้ Extended ACL เพื่อระบุทราฟฟิกที่ต้องการควบคุม

R1(config)# ip access-list extended TELNET
R1(config-ext-nacl)# permit tcp any any eq 23
R1(config-ext-nacl)# exit

R1(config)# ip access-list extended EIGRP
R1(config-ext-nacl)# permit eigrp any any
R1(config-ext-nacl)# exit

R1(config)# ip access-list extended SSH
R1(config-ext-nacl)# permit tcp any any eq 22
R1(config-ext-nacl)# exit

R1(config)# ip access-list extended ICMP
R1(config-ext-nacl)# permit icmp any any
R1(config-ext-nacl)# exit
หมายเหตุ

ACL ที่ไม่มีคำสั่ง permit จะถูกส่งไปยัง Control Plane โดยค่าเริ่มต้น

2
กำหนด Class Map เพื่อจำแนกทราฟฟิก

Class Map จะใช้ ACL ที่สร้างไว้เพื่อจำแนกทราฟฟิก

R1(config)# class-map match-all CM-TELNET
R1(config-cmap)# match access-group name TELNET
R1(config-cmap)# exit

R1(config)# class-map match-all CM-EIGRP
R1(config-cmap)# match access-group name EIGRP
R1(config-cmap)# exit

R1(config)# class-map match-all CM-SSH
R1(config-cmap)# match access-group name SSH
R1(config-cmap)# exit

R1(config)# class-map match-all CM-ICMP
R1(config-cmap)# match access-group name ICMP
R1(config-cmap)# exit

3
กำหนด Policy Map และการควบคุมอัตราทราฟฟิก

Policy Map จะกำหนด อัตราการส่งข้อมูล (policing) และการจัดการทราฟฟิก

R1(config)# policy-map PM-COPP

R1(config-pmap)# class CM-TELNET
R1(config-pmap-c)# police 8000 conform-action drop exceed-action drop
R1(config-pmap-c)# exit

R1(config-pmap)# class CM-EIGRP
R1(config-pmap-c)# police rate 20 pps conform-action transmit exceed-action drop
R1(config-pmap-c)# exit

R1(config-pmap)# class CM-SSH
R1(config-pmap-c)# police 50000 conform-action transmit exceed-action transmit
R1(config-pmap-c)# exit

R1(config-pmap)# class CM-ICMP
R1(config-pmap-c)# police rate 10 pps conform-action transmit exceed-action drop
R1(config-pmap-c)# exit

R1(config-pmap)# class class-default
R1(config-pmap-c)# police 12000 conform-action transmit exceed-action transmit
R1(config-pmap-c)# exit

คำอธิบาย

  • TELNET: จำกัดที่ 8 kbps และ ดรอปทุกแพ็กเก็ต
  • EIGRP: จำกัดที่ 20 pps, อนุญาตถ้าอยู่ในขีดจำกัด, ดรอปถ้าเกิน
  • SSH: จำกัดที่ 50 kbps, อนุญาตทุกแพ็กเก็ต
  • ICMP: จำกัดที่ 10 pps, อนุญาตถ้าอยู่ในขีดจำกัด, ดรอปถ้าเกิน
  • class-default: จำกัดที่ 12 kbps, อนุญาตทุกแพ็กเก็ต
4
นำ Policy Map ไปใช้กับ Control Plane
R1(config)# control-plane
R1(config-cp)# service-policy input PM-COPP
R1(config-cp)# exit
5
ตรวจสอบผลลัพธ์

ดูรายการ ACL ที่กำหนดไว้

R1# show access-lists

ดูรายการ Class Map

R1# show class-map

ดูรายละเอียด Policy Map

R1# show policy-map

ดูสถานะ CoPP และอัตราการจับแพ็กเก็ต

R1# show policy-map control-plane

สรุป

  • CoPP ป้องกัน CPU ของ Control Plane จากทราฟฟิกที่ไม่พึงประสงค์
  • ใช้ ACL เพื่อจำแนกทราฟฟิก
  • ใช้ Class Map เพื่อนำ ACL มาแยกประเภทของทราฟฟิก
  • ใช้ Policy Map เพื่อกำหนดการจัดการทราฟฟิก (Drop / Transmit / Rate-limit)
  • นำ Policy Map ไปใช้กับ Control Plane เพื่อบังคับใช้นโยบาย

วิธีนี้ช่วยให้สามารถ ป้องกัน CPU จากการถูกใช้งานเกินขีดจำกัด และป้องกันการโจมตีที่อาจทำให้ระบบล่ม ได้
