สาระสำคัญเกี่ยวกับ MTU (Maximum Transmission Unit)

นิยามและแนวคิดหลัก

  • MTU (Maximum Transmission Unit) คือขนาดสูงสุดของ "หน่วย" (unit) ที่อุปกรณ์สามารถส่งหรือรับผ่านอินเทอร์เฟซได้ โดยทั่วไปหมายถึงขนาดของแพ็คเก็ต IP รวมส่วนหัว IP แต่ไม่รวมส่วนหัวและส่วนท้ายของเลเยอร์ 2
  • MTU มาตรฐานคือ 1500 ไบต์
  • MTU แบ่งเป็น 2 แนวคิดหลัก: Ethernet MTU และ IP MTU

Ethernet MTU (หรือ Interface MTU)

  • หมายถึงขนาดสูงสุดของเพย์โหลด (payload) ในเฟรม Ethernet
  • เพย์โหลดหมายถึงทุกส่วนยกเว้นส่วนหัวและส่วนท้ายของเฟรม (รวมส่วนหัว Layer 3, Layer 4 และข้อมูล)
  • ถ้าเพย์โหลดมีขนาดใหญ่กว่า MTU ที่กำหนด เฟรมจะถูกทิ้ง เนื่องจาก Layer 2 ไม่มีความสามารถในการแบ่งเฟรม (fragmentation)
  • ขนาดเฟรมมาตรฐานจะอยู่ที่ 1518 ไบต์ (รวมส่วนหัวและส่วนท้าย) หรือ 1522 ไบต์เมื่อใช้ dot1q (เพราะ dot1q tag มีขนาด 4 ไบต์)

IP MTU

  • หมายถึงขนาดสูงสุดของแพ็คเก็ต IP ก่อนที่จะต้องมีการแบ่งแพ็คเก็ต (fragmentation)
  • ค่าเริ่มต้นคือ 1500 ไบต์ เท่ากับ Ethernet MTU
  • ถ้าตั้งค่า DF-bit (Don't Fragment bit) ในส่วนหัว IP แพ็คเก็ตที่มีขนาดใหญ่กว่า IP MTU จะถูกทิ้งแทนที่จะถูกแบ่ง
  • ใช้ได้เฉพาะกับพอร์ต Layer 3 เท่านั้น พอร์ต Layer 2 ของสวิตช์ไม่รองรับ IP MTU
  • IP MTU ไม่สามารถมีค่ามากกว่า Ethernet MTU ได้ แต่สามารถมีค่าน้อยกว่าได้
  • เมื่อเพิ่ม Ethernet MTU ของอินเทอร์เฟซ IP MTU จะเพิ่มโดยอัตโนมัติให้เท่ากัน

System MTU

ช่วยให้สามารถกำหนดค่า MTU เริ่มต้นในระดับระบบได้

  • System MTU: สำหรับอินเทอร์เฟซ 10/100 Mbps
  • System Jumbo MTU: สำหรับอินเทอร์เฟซ 1/10 Gbps
  • System Alternate MTU: ค่า MTU ที่สามกำหนดให้กับอินเทอร์เฟซเฉพาะ
  • Routing MTU: สำหรับพอร์ตที่ทำหน้าที่เราท์ติง

การกำหนดค่า MTU เฉพาะสำหรับอินเทอร์เฟซจะมีความสำคัญเหนือกว่าค่า System MTU

ขนาดเฟรมชนิดต่างๆ

ประเภท ขนาด รายละเอียด
Standard frames 1500 ไบต์ เป็นขนาดมาตรฐานที่ใช้ในเครือข่ายส่วนใหญ่
Jumbo frames มากกว่า 1500 ไบต์ (ทั่วไป 9000-9216 ไบต์) ใช้ในเครือข่ายความเร็วสูง เช่น เซิร์ฟเวอร์ศูนย์ข้อมูล และเครือข่าย iSCSI
Super Jumbo frames มากกว่า 9216 ไบต์ พบน้อยและอุปกรณ์ส่วนใหญ่ไม่รองรับ
Baby giant frames มากกว่า 1500 แต่น้อยกว่า Jumbo (ประมาณ 1600 ไบต์) มักใช้กับโปรโตคอลที่ต้องการ header เพิ่มเติม เช่น MPLS, Q-in-Q

ประโยชน์และข้อเสียของการเพิ่มค่า MTU

ประโยชน์ ข้อเสีย
  • เพิ่มประสิทธิภาพเครือข่ายโดยเพิ่มอัตราส่วนข้อมูลต่อส่วนหัว (data-to-header ratio)
  • ลดจำนวนเฟรมที่ต้องส่งเพื่อข้อมูลปริมาณเดียวกัน
  • ลดภาระการประมวลผลของ CPU บนอุปกรณ์เครือข่าย
  • อาจเพิ่มความล่าช้าในเครือข่าย เนื่องจากแต่ละแพ็คเก็ตใช้เวลาส่งนานขึ้น
  • แพ็คเก็ตขนาดใหญ่มีโอกาสเสียหายมากกว่า หากมีบิตที่เสียหายแม้แต่บิตเดียว ต้องส่งแพ็คเก็ตทั้งหมดใหม่
  • ต้องกำหนดค่าตลอดทั้งเส้นทางเครือข่าย

MTU กับ GRE Tunnels

  • เมื่อใช้ GRE tunnels จะมีส่วนหัว GRE (4 ไบต์) และส่วนหัว IP เพิ่มเติม (20 ไบต์) รวมเป็น 24 ไบต์
  • ถ้าใช้ IP MTU ปกติ 1500 ไบต์ แพ็คเก็ตจะมีขนาดรวม 1524 ไบต์ ซึ่งเกินค่า MTU มาตรฐาน
  • ใน Cisco IOS อินเทอร์เฟซ GRE tunnel จะมี IP MTU เป็น 1476 ไบต์โดยอัตโนมัติ (1500 - 24)
  • Tunnel Transport MTU คือค่าที่คำนวณโดยอัตโนมัติและแสดงขนาดแพ็คเก็ต IP ภายในที่ใหญ่ที่สุดที่สามารถส่งได้โดยไม่ต้องแบ่งแพ็คเก็ต

Path MTU Discovery (PMTUD)

  • เป็นกลไกที่ช่วยให้อุปกรณ์ค้นพบค่า MTU ต่ำสุดในเส้นทางไปยังปลายทาง
  • ช่วยหลีกเลี่ยงการแบ่งแพ็คเก็ต IP ซึ่งต้องใช้การประมวลผลเพิ่มเติม
  • อุปกรณ์ที่เปิดใช้ PMTUD จะตั้งค่า DF-bit ในแพ็คเก็ต IP ขาออกโดยอัตโนมัติ
  • หากอุปกรณ์ในเส้นทางมี MTU เล็กกว่าขนาดแพ็คเก็ต มันจะทิ้งแพ็คเก็ตและส่งข้อความ ICMP Fragmentation Needed กลับไปยังต้นทาง
  • ต้นทางจะลดค่า MTU และส่งแพ็คเก็ตใหม่ จนกว่าแพ็คเก็ตจะสามารถส่งถึงปลายทางได้
ข้อควรรู้
  1. เมื่อเพิ่ม MTU ต้องเพิ่มทุกอินเทอร์เฟซในเส้นทางไปยังปลายทาง มิเช่นนั้นอินเทอร์เฟซที่มี MTU เล็กกว่าจะเป็นจุดคอขวดและป้องกันไม่ให้เฟรมขนาดใหญ่ส่งผ่านเครือข่าย
  2. แพ็คเก็ตที่ได้รับบนอินเทอร์เฟซที่มีขนาดใหญ่กว่า MTU ของอินเทอร์เฟซจะถูกนับเป็น "giants" และถูกทิ้ง
  3. IPv6 MTU เป็นค่าแยกจาก IP MTU และสามารถกำหนดค่าด้วยคำสั่ง IPV6 MTU
  4. โดยทั่วไปไม่จำเป็นต้องเปลี่ยนค่า MTU จากค่าเริ่มต้น 1500 ไบต์ นอกจากกรณีพิเศษ เช่น การใช้ GRE tunnels
