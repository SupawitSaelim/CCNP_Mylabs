MPLS Layer 2 VPN vs Layer 3 VPN

เปรียบเทียบภาพรวม

MPLS VPN เป็นเทคโนโลยีที่นิยมใช้ในเครือข่ายขององค์กรและผู้ให้บริการ เพื่อเชื่อมต่อสาขาต่างๆ เข้าด้วยกันอย่างปลอดภัย โดยแบ่งเป็น 2 ประเภทหลักคือ Layer 2 VPN และ Layer 3 VPN ซึ่งมีความแตกต่างในวิธีการทำงานและการใช้งาน

หัวข้อ MPLS Layer 2 VPN MPLS Layer 3 VPN
การส่งข้อมูล ส่ง "เฟรม" ระดับ Layer 2 (เช่น Ethernet Frame, PPP Frame) ระหว่างสาขา ส่ง "แพ็กเก็ต" ระดับ Layer 3 (IP Packet) โดยทำ Routing ให้เลย
มองจากมุมมองลูกค้า ลูกค้าเหมือนได้ "สาย Ethernet" หรือ "Link Layer 2" ข้ามเมือง ลูกค้าส่ง IP Packet แล้ว Provider จัดการ Routing ทั้งหมดให้
PE Router (Provider Edge) ไม่ยุ่งกับ Routing Table ของลูกค้า (แค่ส่ง Layer 2 Frames) ต้องมี VRF (Virtual Routing and Forwarding) ของแต่ละลูกค้า แยกกัน
ตัวอย่างบริการ - VPWS (Virtual Private Wire Service)
- VPLS (Virtual Private LAN Service)
- EVPN (Ethernet VPN) 		- MPLS L3VPN (RFC 4364)
ความซับซ้อนของ Provider ง่าย (เพราะไม่ต้องสนใจ IP Routing ของลูกค้า) ยาก (ต้อง Manage Routing Table ของลูกค้าหลายราย)

MPLS Layer 2 VPN

สรุปแนวคิด

"ส่ง Layer 2 Frame ผ่าน MPLS Core"

วิธีทำงาน

  • ฝั่ง PE Router จะรับ Ethernet Frame หรือ PPP Frame จากลูกค้า
  • ทำ Encapsulation เป็น MPLS Packet
  • ส่งผ่าน MPLS Backbone
  • ปลายทาง PE ถอดออก ส่ง Ethernet Frame ไปยังลูกค้า

ประเภทของ Layer 2 VPN

VPWS

Virtual Private Wire Service

Point-to-Point L2 Connection (เหมือนสายเช่า Metro Ethernet)

VPLS

Virtual Private LAN Service

L2 Multipoint-to-Multipoint (เหมือนสร้าง LAN เสมือนให้หลาย Site เห็นกันเหมือนอยู่ Hub เดียวกัน)

EVPN

Ethernet VPN

รุ่นใหม่ ใช้ BGP แจก MAC Address (มี Multihoming, Load Balancing ดีขึ้นกว่า VPLS เยอะ)

Protocols ที่ใช้ใน L2VPN

  • LDP (Label Distribution Protocol)
  • BGP (ในกรณี EVPN)
  • Pseudowire Control Word (บางกรณี เช่น VPWS)

ข้อดีของ Layer 2 VPN

  • ลูกค้าควบคุม Routing ได้เอง
  • ง่ายต่อการ Migration จากเครือข่ายเดิม
  • รองรับ Non-IP Protocol
  • Provider ไม่ต้องรู้ IP ของลูกค้า
  • เหมาะกับการเชื่อมต่อ Data Center

ใช้เมื่อไหร่ดี?

เหมาะสำหรับลูกค้าที่:

  • ต้องการควบคุม Routing Protocol เอง
  • มีทีม Network ที่มีความสามารถ
  • ต้องการความยืดหยุ่นสูง
  • ใช้ Protocol พิเศษที่ไม่ใช่ IP

MPLS Layer 3 VPN

สรุปแนวคิด

"ส่ง IP Packet ผ่าน MPLS Core"

วิธีทำงาน

  • ฝั่ง PE Router จะรับ IP Packet จากลูกค้า
  • เลือก VRF ของลูกค้าคนนั้น
  • ทำ Lookup ใน VRF แล้วดูว่าต้องส่งผ่าน Label อะไร
  • ใส่ 2 ชั้น Label
    • Outer Label → ส่งข้าม Core
    • Inner Label → ระบุ VPN

โพรโทคอลที่ใช้

  • MP-BGP (Multiprotocol BGP) = แจก VPNv4/VPNv6 Routes
  • LDP หรือ Segment Routing = แจก Label Path ภายใน Core

หัวใจสำคัญของ MPLS L3VPN

  • VRF (Virtual Routing and Forwarding): Routing Table แยกตามลูกค้า
  • Route Distinguisher (RD): ทำให้ Prefix ของแต่ละลูกค้าไม่ชนกัน
  • Route Target (RT): กำหนดว่าสาขาไหนเห็น Prefix อะไร
  • BGP Label Advertisement: แจกเส้นทาง + Label ผ่าน BGP

ข้อดีของ Layer 3 VPN

  • ลูกค้าไม่ต้องดูแล Routing หลายสาขา
  • รองรับ Topology แบบ Any-to-Any ได้ง่าย
  • รองรับจำนวน Site จำนวนมาก
  • การขยายเครือข่ายทำได้ง่ายกว่า
  • มี QoS และ Traffic Engineering ที่ดี

ใช้เมื่อไหร่ดี?

เหมาะสำหรับลูกค้าที่:

  • ต้องการให้ Service Provider จัดการ Routing
  • มีสาขาจำนวนมาก
  • ต้องการลด Operational Overhead
  • ต้องการสร้าง Virtual Network บน Infrastructure เดียว

รูปแบบสถาปัตยกรรม

แบบบน: MPLS Layer 2 VPN - Customer A Site 1 --- L2 Tunnel --- Customer A Site 2 (ลูกค้าจัดการ IP เอง)

แบบล่าง: MPLS Layer 3 VPN - Customer B Site 1 --- L3 Routed Network --- Customer B Site 2 (Provider ช่วย Routing ให้)

การเปรียบเทียบเชิงลึก

เมื่อดูภาพสถาปัตยกรรมจะเห็นความแตกต่างชัดเจนว่า:

  • L2 VPN: เปรียบเสมือนวางท่อ Layer 2 ระหว่างสาขา โดยลูกค้ายังเห็น Layer 2 ของกันและกัน (MAC Address) และ Router แต่ละสาขาของลูกค้าจะเรียนรู้เส้นทางของกันและกันโดยตรง
  • L3 VPN: เปรียบเสมือนมี Router ตัวกลางที่จัดการ Routing ให้ โดยลูกค้าทั้งสองฝั่งจะส่ง IP Packet ไปยัง Provider Edge (PE) Router แล้ว PE จะจัดการส่งต่อไปยังปลายทาง

✨ สรุปความเข้าใจให้สั้นที่สุด

  • MPLS Layer 2 VPN: Provider เหมือน "ขยายสาย LAN" ให้ข้ามเมือง ลูกค้าทำ IP Routing เอง
  • MPLS Layer 3 VPN: Provider "ช่วยทำ IP Routing" ให้ลูกค้า (มี VRF แยกให้)

ทิศทางในปัจจุบัน

ในปัจจุบัน EVPN กำลังได้รับความนิยมมากขึ้น เนื่องจากสามารถรองรับได้ทั้ง Layer 2 และ Layer 3 VPN (Hybrid) และมีความยืดหยุ่นสูง โดยเฉพาะในการทำ Data Center Interconnect (DCI) และ SD-WAN

🛠️ ข้อพิจารณาในการเลือกใช้

เลือก Layer 2 VPN เมื่อ

  • ต้องการควบคุม Routing Protocol เองทั้งหมด
  • ต้องการให้ Network มีลักษณะเหมือน LAN ข้ามพื้นที่
  • ต้องการรองรับ Non-IP Protocol
  • ต้องการความโปร่งใสของ MAC Address
  • มีทีม Network Engineer ที่มีประสบการณ์
  • กำลังทำ Data Center Interconnect

เลือก Layer 3 VPN เมื่อ

  • ต้องการลดภาระการจัดการ Routing ของตัวเอง
  • มีสาขาจำนวนมาก
  • ต้องการ Scalability สูง
  • ต้องการแยก Traffic ระหว่างแผนกหรือบริษัทย่อย
  • ต้องการความสะดวกในการขยายเครือข่าย
  • ต้องการให้ Service Provider จัดการ QoS ให้
