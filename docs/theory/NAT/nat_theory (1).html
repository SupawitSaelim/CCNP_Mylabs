ทฤษฎีของ NAT (Network Address Translation)

1. NAT คืออะไร

NAT (Network Address Translation) เป็นกระบวนการที่ใช้ในการแปลง IP Address ที่อยู่ภายในเครือข่าย (Private IP) ให้เป็น IP Address ที่สามารถใช้ได้บนอินเทอร์เน็ต (Public IP)

NAT ทำหน้าที่เป็นตัวกลางระหว่างเครือข่ายภายใน (LAN) และเครือข่ายภายนอก (WAN) โดยทำการแปลงที่อยู่ IP เพื่อให้อุปกรณ์ภายในสามารถสื่อสารกับโลกภายนอกได้

ข้อมูลเพิ่มเติม: ช่วงของ Private IP Address ที่ใช้ในเครือข่ายภายใน ตามมาตรฐาน RFC 1918 คือ:
  • 10.0.0.0 - 10.255.255.255 (10.0.0.0/8)
  • 172.16.0.0 - 172.31.255.255 (172.16.0.0/12)
  • 192.168.0.0 - 192.168.255.255 (192.168.0.0/16)

2. ประเภทของ NAT

2.1 Static NAT

  • แปลง IP แบบ 1 ต่อ 1 ระหว่าง Private กับ Public IP
  • ใช้ในกรณีที่ต้องการให้เครื่องภายในเข้าถึงจากภายนอกแบบคงที่
  • เหมาะสำหรับ Server ที่จำเป็นต้องมี Public IP คงที่
  • สิ้นเปลือง Public IP เนื่องจากต้องใช้ 1 IP ต่อ 1 อุปกรณ์

2.2 Dynamic NAT

  • ใช้กลุ่ม Public IP ที่มีจำกัด เพื่อแปลง IP ของเครื่องภายในแบบสุ่ม
  • เมื่อ Public IP ถูกใช้หมด การแปลจะรอจนกว่าจะมี IP ว่าง
  • เหมาะสำหรับเครือข่ายที่มี Public IP หลายตัว แต่ไม่ต้องการใช้มากเท่า Static NAT
  • ไม่เหมาะกับเครือข่ายขนาดใหญ่ที่มีอุปกรณ์จำนวนมาก

2.3 PAT (Port Address Translation)

  • หรือเรียกว่า NAT Overloading
  • แปลงหลาย Private IP ให้ใช้ Public IP เดียว โดยแยกด้วยหมายเลขพอร์ต
  • เป็นรูปแบบที่นิยมใช้ที่สุดในเครือข่ายบ้านและองค์กร
  • ประหยัด Public IP อย่างมาก เนื่องจากใช้พอร์ตเป็นตัวแยกการเชื่อมต่อ

กระบวนการทำงานของ NAT

  1. การเริ่มเชื่อมต่อ: เมื่ออุปกรณ์ในเครือข่ายภายในต้องการเชื่อมต่อกับเครือข่ายภายนอก เช่น อินเทอร์เน็ต
  2. การแปลงที่อยู่: อุปกรณ์ NAT (เช่น Router) จะแปลง Source IP จาก Private IP เป็น Public IP
  3. การสร้างตารางการแปลง: NAT จะบันทึกข้อมูลการแปลงไว้ในตาราง NAT Translation Table
  4. การส่งแพ็คเก็ตออก: แพ็คเก็ตถูกส่งออกไปยังปลายทางด้วย Public IP
  5. การรับแพ็คเก็ตตอบกลับ: เมื่อมีการตอบกลับ อุปกรณ์ NAT จะค้นหาในตารางการแปลง และส่งข้อมูลกลับไปยังอุปกรณ์ภายในที่ถูกต้อง

ในกรณีของ PAT (Overloading) จะมีการบันทึกทั้ง IP Address และ Port Number เพื่อแยกแยะการเชื่อมต่อของแต่ละอุปกรณ์ที่ใช้ Public IP เดียวกัน

3. ประโยชน์ของ NAT

  • ช่วยประหยัดการใช้ Public IP: แก้ปัญหาการขาดแคลน IPv4 โดยใช้ Private IP ภายในเครือข่าย
  • ซ่อนโครงสร้างภายในเครือข่าย: ปกปิดรายละเอียดของโครงสร้างเครือข่ายภายใน ทำให้ยากต่อการโจมตีจากภายนอก
  • เพิ่มความปลอดภัยในระดับหนึ่ง: การเชื่อมต่อจากภายนอกจะถูกบล็อกโดยอัตโนมัติ เว้นแต่จะมีการตั้งค่า Port Forwarding
  • ง่ายต่อการจัดการเครือข่าย: สามารถเปลี่ยนแปลง ISP หรือ Public IP โดยไม่ต้องเปลี่ยนแปลงการตั้งค่าเครือข่ายภายใน
  • รองรับการย้ายหรือรวมเครือข่าย: ช่วยให้สามารถรวมเครือข่ายที่มีช่วง IP ซ้ำกันได้
ข้อจำกัดของ NAT:
  • บางโปรโตคอลและแอปพลิเคชันที่ต้องการการเชื่อมต่อโดยตรงอาจมีปัญหาเมื่อใช้งานผ่าน NAT
  • การทำ Port Forwarding เพิ่มความซับซ้อนในการจัดการ
  • อาจเพิ่มความล่าช้า (Latency) เล็กน้อยเนื่องจากการประมวลผลการแปลงที่อยู่

🔸 คำสั่งที่จำเป็นสำหรับ NAT บน Cisco IOS

1. สร้าง ACL เพื่อระบุ Traffic ที่จะทำ NAT

access-list 1 permit 192.168.1.0 0.0.0.255

2. กำหนด NAT Overload (PAT)

ip nat inside source list 1 interface FastEthernet0/0 overload

3. ระบุ Interface ที่อยู่ภายใน (inside) และภายนอก (outside)

interface FastEthernet0/1 ip address 192.168.1.1 255.255.255.0 ip nat inside interface FastEthernet0/0 ip address 203.0.113.1 255.255.255.0 ip nat outside

4. สำหรับ Static NAT

ip nat inside source static 192.168.1.100 203.0.113.100

5. สำหรับ Dynamic NAT

ip nat pool PUBLIC 203.0.113.10 203.0.113.20 netmask 255.255.255.0 ip nat inside source list 1 pool PUBLIC

คำสั่งสำหรับ Port Forwarding

ip nat inside source static tcp 192.168.1.100 80 203.0.113.1 80

คำสั่งตรวจสอบการทำงานของ NAT

show ip nat translations show ip nat statistics

คำสั่งลบ NAT Translation ที่มีอยู่

clear ip nat translation *

คำสั่ง Debug NAT

debug ip nat

เนื้อหาเพิ่มเติม: NAT ขั้นสูง

ในโลกของ IPv6 แนวคิดของ NAT มีการเปลี่ยนแปลง เนื่องจาก IPv6 มีจำนวน IP Address มากพอที่จะรองรับอุปกรณ์ทุกชิ้นในโลก โดยไม่จำเป็นต้องใช้ NAT เพื่อประหยัด IP

NAT64 และ DNS64

เป็นเทคโนโลยีที่ช่วยให้เครือข่าย IPv6 สามารถสื่อสารกับเครือข่าย IPv4 ได้ โดย:

  • NAT64: แปลงแพ็คเก็ตระหว่าง IPv6 และ IPv4
  • DNS64: สร้าง IPv6 Address สำหรับเว็บไซต์ที่มีเฉพาะ IPv4 เพื่อให้อุปกรณ์ IPv6 สามารถเชื่อมต่อได้

NPTv6 (Network Prefix Translation)

NPTv6 เป็นรูปแบบของ NAT สำหรับ IPv6 ที่แปลงเฉพาะ Prefix ของเครือข่าย โดยไม่เปลี่ยนส่วน Interface ID ทำให้การติดตามและความเป็นส่วนตัวยังคงอยู่

NAT Traversal คือวิธีการที่ช่วยให้การเชื่อมต่อสามารถผ่าน NAT ได้ โดยเฉพาะสำหรับแอปพลิเคชันที่ต้องการการเชื่อมต่อแบบ Peer-to-Peer

เทคนิค NAT Traversal

  • STUN (Session Traversal Utilities for NAT): ช่วยให้อุปกรณ์ค้นหา Public IP และประเภทของ NAT
  • TURN (Traversal Using Relays around NAT): ใช้เซิร์ฟเวอร์กลางเพื่อส่งต่อข้อมูลระหว่างอุปกรณ์
  • ICE (Interactive Connectivity Establishment): รวมเทคนิค STUN และ TURN เข้าด้วยกัน
  • UPnP (Universal Plug and Play): อนุญาตให้แอปพลิเคชันเปิดพอร์ตบนอุปกรณ์ NAT โดยอัตโนมัติ
ความปลอดภัย: UPnP มีความเสี่ยงด้านความปลอดภัย เนื่องจากอนุญาตให้แอปพลิเคชันเปิดพอร์ตโดยไม่มีการตรวจสอบยืนยัน ควรใช้ด้วยความระมัดระวัง

CGNAT หรือ LSN (Large-Scale NAT) เป็นเทคโนโลยีที่ ISP ใช้เพื่อแบ่งปัน Public IP ให้กับลูกค้าหลายราย

การทำงานของ CGNAT

  • ISP จัดสรร Private IP (ส่วนใหญ่เป็นช่วง 100.64.0.0/10) ให้กับลูกค้า
  • อุปกรณ์ CGNAT ของ ISP ทำการแปลง Private IP เหล่านี้เป็น Public IP
  • ลูกค้าจะเชื่อมต่อกับอินเทอร์เน็ตผ่าน NAT 2 ชั้น:
    • NAT ชั้นแรกคือที่อุปกรณ์ของลูกค้า (เช่น Router บ้าน)
    • NAT ชั้นที่สองคือที่อุปกรณ์ CGNAT ของ ISP
ผลกระทบของ CGNAT:
  • การทำ Port Forwarding จะทำได้ยากหรือไม่สามารถทำได้
  • บางแอปพลิเคชัน เช่น เกมออนไลน์ อาจมีปัญหาในการเชื่อมต่อ
  • การติดตาม IP เพื่อระบุผู้ใช้จะซับซ้อนขึ้น เนื่องจากหลายผู้ใช้อาจใช้ IP เดียวกัน

เปรียบเทียบประเภทของ NAT

การสิ้นเปลือง Public IP สูง ปานกลาง ต่ำ

การใช้งานทั่วไป Server, บริการสาธารณะ เครือข่ายขนาดกลาง เครือข่ายทั่วไป, บ้าน, องค์กร

การแก้ไขปัญหาทั่วไปเกี่ยวกับ NAT

1. ไม่สามารถเชื่อมต่อออกสู่อินเทอร์เน็ตได้

  • ตรวจสอบการกำหนด inside/outside interface ว่าถูกต้อง
  • ตรวจสอบ ACL ว่าครอบคลุมเครือข่ายภายในทั้งหมด
  • ตรวจสอบการเชื่อมต่อ Interface ภายนอกว่าทำงานปกติ
  • ใช้คำสั่ง debug ip nat เพื่อดูการทำงานของ NAT แบบ Real-time

2. บางบริการทำงานไม่ได้ผ่าน NAT

  • บางโปรโตคอลอาจต้องการการตั้งค่าพิเศษ เช่น SIP, H.323, FTP
  • พิจารณาใช้ ALG (Application Layer Gateway) ในอุปกรณ์
  • ตรวจสอบว่าแพ็คเก็ตไม่ใหญ่เกินไปจนเกิดการ Fragment

3. ตารางการแปลง NAT เต็ม

  • เพิ่ม Timeout ของ NAT Translations โดยใช้คำสั่ง ip nat translation timeout [seconds]
  • ลด Timeout สำหรับ Protocol ที่ไม่จำเป็นต้องคงการเชื่อมต่อนาน
  • ตรวจสอบการ Leak ของ Connection โดยใช้คำสั่ง show ip nat translations verbose

สรุป

NAT เป็นเทคโนโลยีสำคัญที่ช่วยแก้ปัญหาการขาดแคลน IPv4 และเพิ่มความปลอดภัยให้กับเครือข่าย ในปัจจุบันแม้จะมี IPv6 แล้ว แต่ NAT ยังคงมีบทบาทสำคัญในการจัดการเครือข่ายและการรักษาความปลอดภัย การเลือกใช้ประเภทของ NAT ที่เหมาะสมกับความต้องการและการตั้งค่าอย่างถูกต้องจะช่วยให้เครือข่ายทำงานได้อย่างมีประสิทธิภาพและปลอดภัย
