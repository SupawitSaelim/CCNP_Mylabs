ทฤษฎีของ GLBP (Gateway Load Balancing Protocol)

📌 ภาพรวม

GLBP (Gateway Load Balancing Protocol) เป็นโปรโตคอลจาก Cisco ที่ใช้สำหรับทำ Gateway redundancy (คล้าย HSRP/VRRP) แต่มีจุดเด่นคือ สามารถกระจายโหลด (load balancing) ให้หลาย gateway ใช้งานพร้อมกันได้

จุดเด่นของ GLBP

  • Load Balancing: สามารถใช้ประโยชน์จากทุก gateway พร้อมกัน ไม่มี gateway ที่ว่างเปล่า
  • Cisco Proprietary: เป็นเทคโนโลยีจาก Cisco แต่นำมาใช้ได้กับอุปกรณ์ Cisco ทั้งหมด
  • Automatic Failover: เมื่อ gateway ใดล่ม จะเปลี่ยนไปใช้ gateway อื่นโดยอัตโนมัติ
  • Flexible Configuration: รองรับวิธีการกระจายโหลดหลายรูปแบบ

หลักการทำงาน

การทำงานของ GLBP แตกต่างจาก HSRP/VRRP ตรงที่:

  1. เมื่อ Client ทำ ARP request หา Gateway IP (192.168.99.254)
  2. AVG (Active Virtual Gateway) จะตอบด้วย Virtual MAC Address ของ AVF (Active Virtual Forwarder) ตัวใดตัวหนึ่ง
  3. Client จะส่ง packet ไปยัง MAC Address ที่ได้รับ
  4. AVF ที่รับผิดชอบ MAC นั้นจะทำการ forward packet ต่อไป
  5. เมื่อ Client ใหม่ทำ ARP request, AVG จะแจก MAC Address ตามวิธีการ load balancing ที่กำหนด

รูปแบบของ Virtual MAC Address

GLBP จะสร้าง Virtual MAC Address ในรูปแบบ:

0007.b400.XXYY

  • 0007.b400 - เป็นค่าคงที่ของ GLBP
  • XX - คือ GLBP group number ในรูปแบบเลขฐาน 16
  • YY - คือ AVF number (01, 02, 03, ...)

💡 ข้อดีของ GLBP เมื่อเทียบกับ HSRP/VRRP

  • ใช้ทรัพยากรคุ้มค่า: โดยปกติ HSRP/VRRP จะมี gateway หลักทำงานเพียงตัวเดียว แต่ GLBP ใช้ทุกตัวพร้อมกัน
  • กระจายโหลดอัตโนมัติ: ไม่ต้องตั้งค่าหลาย group เพื่อทำ load balancing แบบ manual
  • ลดความซับซ้อน: ใช้ Virtual IP เพียงตัวเดียว ง่ายต่อการจัดการ

📌 องค์ประกอบหลักของ GLBP

1. AVG (Active Virtual Gateway)
  • มีหน้าที่ตอบ ARP Request ด้วย MAC ของ AVF แต่ละตัว (แจก MAC แบบ round-robin โดยค่าเริ่มต้น)
  • เลือกจากตัวที่มี priority สูงสุด (default = 100)
  • ถ้ามีค่า priority เท่ากัน จะดูจาก IP address สูงสุด
  • ในกลุ่ม GLBP หนึ่งๆ จะมี AVG เพียงตัวเดียว
  • ถ้า AVG ล่ม จะมีการเลือก AVG สำรองขึ้นมาทำหน้าที่แทน
2. AVF (Active Virtual Forwarder)
  • เป็นตัวที่ใช้ MAC ที่ AVG แจกให้
  • แต่ละ AVF จะรับผิดชอบ MAC ของตัวเอง และ forward traffic ให้กับ host ที่ได้ MAC ตัวนั้น
  • Router ทุกตัวในกลุ่ม GLBP จะเป็น AVF
  • GLBP รองรับได้สูงสุด 4 AVF ต่อ group
  • แต่ละ AVF จะมี state เช่น Active, Listen, Disabled
3. Preemption
  • AVG Preemption ต้องกำหนดด้วยคำสั่ง glbp <grp> preempt
  • เมื่อเปิดใช้งาน router ที่มี priority สูงกว่าจะแย่งเป็น AVG เมื่อกลับมาออนไลน์
  • AVF Preemption เปิดโดยอัตโนมัติอยู่แล้ว
  • สามารถตั้งค่า delay ได้เพื่อป้องกัน flapping
4. Load Balancing Method
  • Round-robin (ค่าเริ่มต้น): แจก MAC ตามลำดับ หมุนเวียนไปเรื่อยๆ
  • Weighted: แจก MAC ตามค่าน้ำหนักที่กำหนด router ที่มีน้ำหนักมากกว่าจะได้รับ traffic มากกว่า
  • Host-dependent: host เดิมจะได้ MAC เดิมเสมอ ทำให้ session ต่อเนื่อง
5. Authentication
  • ป้องกัน router ปลอมแปลงเข้าร่วมกลุ่ม
  • ใช้ md5 key-string หรือ key-chain
  • เพิ่มความปลอดภัยให้กับการสื่อสารระหว่าง router ในกลุ่ม
6. Object Tracking + Weighting
  • ใช้ตรวจสอบสถานะของ interface เช่น Loopback
  • เมื่อ interface ล่ม น้ำหนักจะลดลง และ router จะยอมสละบทบาท AVF
  • ทำให้การ failover ชาญฉลาดขึ้น ไม่ใช่แค่ตรวจสอบว่า router ยังทำงานอยู่หรือไม่

GLBP Message Types

GLBP ใช้ multicast address 224.0.0.102 และ UDP port 3222 ในการส่งข้อความระหว่าง router

  • Hello: ส่งทุก 3 วินาที เพื่อแจ้งว่ายังทำงานอยู่
  • Request/Reply: ใช้ในการเลือก AVG และ AVF
  • Coup: ส่งเมื่อต้องการแย่งตำแหน่ง AVG หรือ AVF
  • Resign: ส่งเมื่อ router ต้องการสละตำแหน่ง

💡 GLBP State Machine

GLBP มีสถานะที่แตกต่างกันสำหรับ AVG และ AVF:

  • AVG States: Disabled, Listen, Speak, Standby, Active
  • AVF States: Disabled, Listen, Active

🧾 คำสั่งที่จำเป็นสำหรับ GLBP

1. ตั้งค่า GLBP (IPv4)

interface vlan 99
glbp 99 ip 192.168.99.254
glbp 99 priority 150
glbp 99 preempt

2. ตั้งค่า GLBP (IPv6)

interface vlan 99
glbp 996 ipv6 fe80::99:254
glbp 996 priority 150
glbp 996 preempt

3. แสดงสถานะ GLBP

show glbp
show glbp brief

4. ตั้งค่า Authentication

interface vlan 99
glbp 99 authentication md5 key-string Super53cret
glbp 996 authentication md5 key-string Super53cret

5. Object Tracking + Weighting

track 7 interface loopback0 line-protocol

interface vlan 99
glbp 99 weighting 110 lower 85 upper 105
glbp 99 weighting track 7 decrement 30
glbp 996 weighting 110 lower 85 upper 105
glbp 996 weighting track 7 decrement 30

6. ตั้งค่า Load Balancing

interface vlan 99
glbp 99 load-balancing round-robin

! หรือ
glbp 99 load-balancing weighted

! หรือ
glbp 99 load-balancing host-dependent

7. ตั้งค่าเวลา Timers

interface vlan 99
glbp 99 timers hello 5 hold 15

8. ตั้งค่า Preemption Delay

interface vlan 99
glbp 99 preempt delay minimum 60

⚠️ ข้อควรระวัง

  • เมื่อกำหนด GLBP group number ควรใช้เลขเดียวกันในทุก router ที่เป็นสมาชิกกลุ่มเดียวกัน
  • หากใช้ authentication ต้องตั้งค่า key-string เดียวกันทุก router
  • ค่า priority และ weighting มีผลต่อการเลือก AVG และ AVF

🧪 ทดสอบการทำงาน

  • ใช้คำสั่ง arp -a บน PC เพื่อตรวจสอบว่า MAC ของ gateway ถูกสลับใช้งานหรือไม่
  • ทดลอง shutdown interface เพื่อดูว่า AVF อื่นเข้ามาแทนที่หรือไม่
  • ตรวจสอบสถานะด้วยคำสั่ง show glbp เพื่อดูรายละเอียดของ AVG และ AVF

GLBP ขั้นสูง

1. การตั้งค่า Weighted Load Balancing

การตั้งค่า weighted load balancing เพื่อให้ router บาง router รับ traffic มากกว่าตัวอื่น:

! Router A (รับ traffic 50%)
interface vlan 99
glbp 99 weighting 150
glbp 99 load-balancing weighted

! Router B (รับ traffic 33%)
interface vlan 99
glbp 99 weighting 100
glbp 99 load-balancing weighted

! Router C (รับ traffic 17%)
interface vlan 99
glbp 99 weighting 50
glbp 99 load-balancing weighted

2. การใช้ IP SLA กับ GLBP

การตรวจสอบการเชื่อมต่อไปยัง upstream router และปรับ weight ตามสถานะ:

! สร้าง IP SLA
ip sla 10
icmp-echo 10.1.1.1 source-interface GigabitEthernet0/1
frequency 5
ip sla schedule 10 life forever start-time now

! สร้าง tracking
track 10 ip sla 10 reachability

! ผูกกับ GLBP
interface vlan 99
glbp 99 weighting 110 lower 85 upper 105
glbp 99 weighting track 10 decrement 25

3. การใช้ Key-Chain Authentication

การใช้ key-chain เพื่อความปลอดภัยที่มากขึ้น:

! สร้าง key chain
key chain GLBP-AUTH
key 1
key-string Super53cret

! ผูกกับ GLBP
interface vlan 99
glbp 99 authentication md5 key-chain GLBP-AUTH

4. การตั้งค่า GLBP หลายกลุ่มบน interface เดียวกัน

การตั้งค่า GLBP หลายกลุ่มเพื่อรองรับหลาย subnet:

interface vlan 99
ip address 192.168.99.1 255.255.255.0
glbp 99 ip 192.168.99.254
glbp 99 priority 150

interface vlan 99.100
encapsulation dot1q 100
ip address 192.168.100.1 255.255.255.0
glbp 100 ip 192.168.100.254
glbp 100 priority 100

💡 การออกแบบ GLBP อย่างมีประสิทธิภาพ

  1. เลือก load balancing method ให้เหมาะสม:
    • Round-robin: เหมาะกับ traffic ที่กระจายสม่ำเสมอ
    • Weighted: เหมาะเมื่อมี router ที่มีประสิทธิภาพต่างกัน
    • Host-dependent: เหมาะกับ application ที่ต้องการความต่อเนื่องของ session
  2. ใช้ tracking อย่างเหมาะสม: track interface สำคัญ หรือ track การเชื่อมต่อไปยัง upstream router
  3. ตั้งค่า timer ให้เหมาะสม: timer สั้นเกินไปอาจทำให้เกิด network overhead, timer นานเกินไปอาจทำให้การ failover ช้า
  4. ใช้ authentication: เพิ่มความปลอดภัยให้กับ GLBP โดยเฉพาะในเครือข่ายที่มีความเสี่ยง
  5. วางแผนการใช้ preemption: พิจารณาผลกระทบต่อเครือข่ายเมื่อมีการเปลี่ยน AVG

5. การใช้งาน GLBP กับ IPv6

GLBP สามารถทำงานกับ IPv6 ได้เช่นกัน:

interface vlan 99
ipv6 address 2001:db8:99::1/64
ipv6 enable
glbp 996 ipv6 2001:db8:99::ffff
glbp 996 priority 150
glbp 996 preempt
glbp 996 load-balancing host-dependent

การออกแบบเครือข่ายที่ซับซ้อน

สำหรับเครือข่ายที่ซับซ้อน อาจใช้การผสมผสานระหว่าง GLBP, HSRP และ VRRP:

  • GLBP: ใช้สำหรับเครือข่ายที่ต้องการ load balancing ที่มีประสิทธิภาพ
  • HSRP: ใช้สำหรับเครือข่ายที่ต้องการความเข้ากันได้กับอุปกรณ์ Cisco
  • VRRP: ใช้สำหรับเครือข่ายที่มีอุปกรณ์หลากหลายยี่ห้อ

6. การแก้ไขปัญหา GLBP

debug glbp events
debug glbp errors
debug glbp packets
debug glbp terse

⚠️ ข้อจำกัดของ GLBP

  • รองรับได้สูงสุด 4 AVF ต่อ group
  • ไม่รองรับ stateful failover
  • เป็นเทคโนโลยีเฉพาะของ Cisco
  • ไม่รองรับการทำงานร่วมกับ HSRP/VRRP บน interface เดียวกัน

เมื่อไรควรเลือกใช้ GLBP?

  • เมื่อต้องการใช้ทุก router ในการรับส่งข้อมูลพร้อมกัน
  • เมื่อต้องการกระจายโหลดระหว่าง gateway อย่างอัตโนมัติ
  • เมื่อต้องการความซับซ้อนในการจัดการที่น้อย (ใช้เพียง Virtual IP เดียว)
  • เมื่อต้องการปรับแต่งวิธีการ load balancing ให้เหมาะสมกับเครือข่าย

สรุป

GLBP เป็นโปรโตคอลที่เหมาะสำหรับเครือข่ายที่ต้องการประสิทธิภาพสูงสุดจากทรัพยากร gateway ที่มีอยู่ แต่ในขณะเดียวกันก็มีข้อจำกัดในแง่ของการใช้งานเฉพาะอุปกรณ์ Cisco เท่านั้น การเลือกใช้ GLBP, HSRP หรือ VRRP ขึ้นอยู่กับความต้องการของเครือข่ายและอุปกรณ์ที่มีอยู่
