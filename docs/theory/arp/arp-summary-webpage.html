ARP Protocol

Address Resolution Protocol - สรุปสาระสำคัญ

ความสัมพันธ์ระหว่าง Layer 2 และ Layer 3

  • Layer 3 (IP): ให้การระบุตำแหน่งแบบ end-to-end จากต้นทางถึงปลายทาง ทำงานได้ทั้งกับอุปกรณ์ที่เชื่อมต่อโดยตรงและไม่โดยตรง
  • Layer 2 (MAC): ให้การระบุตำแหน่งแบบ hop-to-hop ในแต่ละเซกเมนต์เครือข่าย ทำงานเฉพาะกับอุปกรณ์ที่เชื่อมต่อกันโดยตรง
  • ARP: เป็นสะพานเชื่อมระหว่าง Layer 2 และ Layer 3 ใช้แปลง IP Address เป็น MAC Address
ความสัมพันธ์ระหว่าง Layer 2 และ Layer 3

ARP Message Format

ARP Packet Format
Hardware Type
1 = Ethernet
Protocol Type
0x0800 = IPv4
Hardware Address Length
6 bytes (MAC)
Protocol Address Length
4 bytes (IPv4)
Operation
1 = Request, 2 = Reply
Sender Hardware Address
MAC Address ของผู้ส่ง
Sender Protocol Address
IP Address ของผู้ส่ง
Target Hardware Address
MAC ผู้รับ (0s ใน Request)
Target Protocol Address
IP Address ของผู้รับ

หมายเหตุ: ARP messages ถูกบรรจุโดยตรงใน Ethernet frame โดยไม่มี IP header และมี EtherType เป็น 0x0806

ARP Process

1

ตรวจสอบ ARP Cache ก่อนส่งแพ็กเก็ต ถ้ามี entry อยู่แล้วจะใช้ MAC address นั้นได้เลย

2

ถ้าไม่มี entry จะสร้าง 'incomplete' entry ก่อน

3

ส่ง ARP Request แบบ broadcast (Destination MAC: FF-FF-FF-FF-FF-FF)

4

อุปกรณ์ปลายทางที่มี IP ตรงกับ Target Protocol Address จะส่ง ARP Reply แบบ unicast ตอบกลับ

5

อัพเดท ARP Cache จาก 'incomplete' เป็น complete entry พร้อมบันทึก MAC address

ARP Timeout

  • ค่า default ARP timeout: 4 ชั่วโมง (14400 วินาที) ใน Cisco IOS
  • Random Jitter: เพิ่ม 0-30 นาทีเพื่อป้องกัน ARP storm (การหมดอายุพร้อมกันของหลาย entries)
  • Incomplete entries: หมดอายุใน 1 นาที
arp timeout 14400

เมื่อ entry หมดอายุ อุปกรณ์จะพยายามส่ง unicast ARP request 3 ครั้งก่อนลบ entry:

  1. ครั้งที่ 1: เมื่อ timer หมด
  2. ครั้งที่ 2: หลังจากรอ 1 นาที
  3. ครั้งที่ 3: หลังจากรอเพิ่มอีก 1 นาที ถ้ายังไม่ได้รับตอบจะลบ entry

Clear ARP Process

คำสั่ง clear arp ไม่ได้ลบ entries ทันที แต่จะพยายาม refresh entries ก่อน:

  1. ส่ง unicast ARP request ไปยังทุก entry
  2. ถ้าได้รับ reply, entry จะถูก refresh แทนที่จะถูกลบ
  3. ถ้าไม่ได้รับตอบหลัง 3 ครั้ง entry จะถูกลบ

สำคัญ: นี่แตกต่างจากคำสั่ง clear mac address-table dynamic ที่จะลบ entries ทันทีโดยไม่มีการพยายาม refresh

Proxy ARP

Proxy ARP อนุญาตให้อุปกรณ์ (มักเป็น router) ตอบ ARP requests แทนอุปกรณ์อื่น

หมายเหตุ: Proxy ARP เปิดใช้งานเป็นค่า default ใน Cisco IOS ทั้งในระดับ global และระดับ interface

ใช้ในกรณี:

  • Subnet mask ไม่ตรงกัน
  • Directly connected static routes
  • บางสถานการณ์ของ NAT

คำสั่งที่เกี่ยวข้อง:

# ปิด/เปิด global [no] ip arp proxy disable # ปิด/เปิดบน interface [no] ip proxy-arp # ตรวจสอบสถานะ show ip interface [interface-name]

Gratuitous ARP

Gratuitous ARP เป็น ARP Reply ที่ส่งโดยไม่ได้รับ ARP Request ก่อน

คุณสมบัติ รายละเอียด
Operation code 2 (เหมือน ARP Reply)
Source/Destination IP เป็น IP เดียวกัน (ของผู้ส่ง)
Destination MAC Broadcast (FF-FF-FF-FF-FF-FF)

ใช้สำหรับ:

  • ประกาศเมื่อ interface เปิดใช้งาน
  • ประกาศการเปลี่ยนแปลง MAC address
  • ใช้ระหว่าง failover ในโปรโตคอล FHRP (เช่น HSRP, VRRP)

พฤติกรรมใน Cisco IOS: จะ refresh existing entry หากได้รับ gratuitous ARP แต่จะไม่สร้าง entry ใหม่

คำสั่ง คำอธิบาย
show arp หรือ show ip arp แสดง ARP table
